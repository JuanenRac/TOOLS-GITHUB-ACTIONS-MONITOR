# 操作ログ

Complete のみ、初期状態はオンです。アクセスの監査（ログイン、ロック、拒否）とは別に、モニターは **操作** のログを保持します。誰が、いつ、どのアカウントで何を変更したかです。設定の変更、サイレンスとその解除、ユーザー・パスワード・通知設定・認証情報の変更が対象です。1 件ごとに 1 行の JSON として `logs/audit_actions.jsonl` に追記され、書き換えられることはありません。 確認された操作も記録します。GitHub 上の操作（再実行、キャンセル、ディスパッチ、マージ）、`act` による実行、保存されたトークンの保存または削除、動作モードの変更、検出で追加されたグループ、追加された教訓、今書き出されたレポート、アカウントのログイン、AI の操作です。行には確認された内容と結果が残り、リクエスト本文は決して記録されません。すべての POST ルートは、記録されるか、理由付きで除外として一覧されるかのどちらかで、新しいルートがどちらでもない場合はテストが失敗します。

## 1 行の内容

`at`、`action`（`settings_change` や `alert_mute` のような単純な語）、`user`、`role`、`account`、`target`（設定名やアラートコードなどの短い識別子）、`result`（`ok`、`denied`、`error`）、必要に応じて `details`。**値や秘密は決して書かれません**。設定の変更では設定の名前のみを書き、値は書きません。名前が秘密らしく見えるキー（token、password、key、cookie、authorization、session など）は除外され、すべてのテキストは AI 向けのメモと同じ方法でクリーニングされ、200 文字に切り詰められます。

## ハッシュの連鎖

各行は `prev`（直前の行のハッシュ）と `hash`（その行自身と `prev` のハッシュ）を持ちます。後から変更・削除・挿入された行は連鎖を壊し、`GET /api/audit-log` がその位置（`chain.broken_at`）を示します。`audit_log.max_mb` を超えると古い部分は `audit_actions.jsonl.1` として保持され、連鎖は新しいファイルで続きます。連鎖は改ざんを示しますが、ファイルにアクセスできる人が全体を削除することは防げません。重要な場所にコピーを保管してください。 複数のアカウントでは、各アカウントが自分のフォルダに専用のファイル（`accounts/<id>/audit_actions.jsonl`）を持ち、API は問い合わせたアカウントの行だけを返します。この変更より前に書かれた行は、これまでの共有ファイルに残ります。検証はローテーション済みファイルと両者のつながりも対象にします（`segments`、行が壊れているときは `segment`）。`complete: false` は、ローテーション済みファイルが後のローテーションで置き換えられたか削除されたため、チェーンが最初の鎖から始まっていないことを示します。複数のプロセスが同じファイルに書き込めます。各行は、ロックの下で、実際にファイルにある最後の行につながれます。チェーンには秘密鍵がありません。ファイルを書き込める人は、最新の行を切り取ったり、新しいハッシュで書き直したりできます。証拠として使うなら、別の場所にコピーを保管してください。 `audit_log.keep_generations`(既定 5、1〜20)を使うと、古い部分は `.1`、`.2` のように保持されます。最新が `.1` で、その数より古いものは削除され、`GET /api/audit-log` はそれらすべてにわたってチェーンを検証します。

## 読める人

管理者（チームモードがない場合はコンピューターの前にいる人）。メンテナーは `audit_log.maintainers_can_read` がオンのときだけ読めます。それ以外の人は読めません。`GET /api/audit-log` は直近 200 行と連鎖の状態を返します。Lite にはありません。 viewer は入口で拒否されます。ログをオフにすると、そのログ自身の最後の行（オフにした変更）が書き込まれます。書き込めなかった行は数えられ、回答の `write_failures` と `last_write_error_at`、および劣化の通知に出ます。自分のパスワード変更の失敗はここには書かれません（アクセスの監査が保持します）。

## 設定

設定、センチネルタブ、ブロック **操作ログ**：`audit_log.enabled`（オン）、`audit_log.max_mb`（10）、`audit_log.maintainers_can_read`（オフ）。 `audit_log.keep_generations`(5)は保持する回転済みファイルの数です。`audit_log.required`(オフ)をオンにすると、記録が必要な操作(GitHub 上の操作の確認、モード、ミュート、認証情報など)は、ログに書き込めない間 503 で拒否されます。直せるように設定は開いたままです。

今すぐ作成したバックアップ (`POST /api/ops/backup`) とオンデマンドの削除 (`POST /api/ops/purge`、ドライランも) は `backup_run` と `purge_run` として記録されます。行には要求した人と結果が残り、バックアップの内容は残りません。

# The Settings tab

The Settings tab (the Settings entry of the side panel) changes the values of `actions_monitor.json` from the page, so nobody has to edit the file by hand.
It is written in the eight languages of the page and follows the look of the rest of it.

<!-- settings:begin -->
## What can be changed

Only the keys of the list in `settings_api.py` (the schema). Each one has a type and a range, and the page says whether a change needs a **restart** of the monitor (the loop reads its configuration once) or **applies now**.

The tab is split into sub-tabs, ordered from the common to the advanced: This browser, Basic, General, Refresh and limits, Sentinel, Surface checks (A10), Readiness (A11), Folders and files, Outputs, then the integrations. Inside a sub-tab the settings are grouped in titled blocks; the first field of a block is its main switch and, while it is off, the rest of the block is dimmed and cannot be edited. Every field shows its unit (s, min, h, days, MB, calls), its range, a badge (needs a restart / applies now), a badge for the safety options that start in their conservative state, and one line of help. The search box filters the settings of all the sub-tabs; each sub-tab counts its unsaved changes; the Save and Discard buttons stay visible; the sub-tab you used last is remembered by the browser. The tabs follow the keyboard pattern of tabs (arrow keys, Home, End).

A setting appears in one place only. Read-only: `webhook.signing_state` only says whether the shared secret is defined; the secret itself is never shown.

Which repositories are watched: the example catalogue of ecosystems ends with a group `rest` (prefix `*`, "Everything else") that takes every repository no other group claims, so nothing is left out by default. If your own catalogue leaves repositories out, a banner of the page says how many ("your ecosystem filter hides N of the M repositories of the account").

External AI: `ai.provider` can be `ollama` (this computer), `openai-compatible` (any OpenAI-style endpoint, which also serves Gemini through its OpenAI-compatible endpoint and OpenAI itself), `anthropic` (the Messages API; you choose the model) or `copilot` (`gh copilot` with your own login; it spends premium requests). The key is never saved: only the NAME of the environment variable. See AI.md.

### Example of pin sources

The pins are read only when a source is listed; with an empty list nothing is read and the page says so. The text below is an example, commented out:

```jsonc
// Example, commented out: where the pinned versions of an ecosystem live. Copy the part you need into
// "sentinel" > "readiness" > "pins" > "sources" of actions_monitor.json (or paste it in the Settings tab) and remove the comments.
// [
//   {"ecosystem": "alpha", "kind": "pin_table", "provider": "ALPHA-COMMON", "file": "pins/consumers.json", "key": "consumers"},
//   {"ecosystem": "beta",  "kind": "lock_files", "provider": "BETA-CORE", "lock_name": "beta.lock.json", "version_key": "core"}
// ]
// pin_table: a JSON file of the provider that maps each repository to the version it pins (under "key").
// lock_files: every clone is searched (down to "max_depth" folder levels) for files called "lock_name"; the OLDEST version found in "version_key" counts.
```

## What can never be changed or seen from the page

Tokens, secrets, signature keys, the webhook secret, the command the sentinel can run (`sentinel.notify_command`), the API key of the AI (only the name of its environment variable can be set) and any key of another tool: they are **not in the
schema**, so the page neither shows nor writes them, and a request that names one is refused. Every other key of the file is kept exactly as it was.

## How a save works

1. Only the values that changed are sent, as `POST /api/settings` with `Content-Type: application/json` and a body of at most 16 KB.
2. Every value is checked against its type and range; one invalid value refuses the whole request and nothing is written. Paths must be text without control characters, never a
   network (UNC) path and never on the `D:` drive.
3. The previous file is copied to `config_backups/actions_monitor-<time>.json` (the last ten copies are kept).
4. The new file is written to a temporary file and moved over the old one (atomic), so a crash never leaves half a file. A file that is not valid JSON is never overwritten from the page.
5. The page says which saved values need a restart and keeps a banner until you restart.

## Who may ask

Only the page of the same machine: the server listens on `127.0.0.1` and refuses a request whose `Host` or `Origin` is not its own address (the same checks as every other endpoint).
A cross-site form cannot reach it because the request must be JSON.

## Before 1.5.0

The language of the tools was decided by the language of the system; now they start in English and the language is a setting (here, `language`, `MONITOR_LANG` or `--lang`).
`parte_history_days` is now `report_history_days` (the old name is still read).

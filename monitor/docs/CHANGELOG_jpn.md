# 変更履歴

ツール自体(モニター + センチネル + バッチツール)のバージョンで、独自のセマンティックバージョニングです。元は英語の CHANGELOG.md で、このファイルは同じバージョンと節を持ちます。

## [Unreleased]

### 変更

- **フォルダ構成を刷新、動作は同じ**:コードはインポート可能なパッケージとして `src/github_actions_monitor/`(`app`、`accounts`、`sentinels`、`security`、`data_pipeline`、`integrations`、`cli`、`ui`、`i18n`、`util`)に置かれ、ページ、中立のサンプルと `quotas.json`、8 言語のカタログは `assets/`(`static`、`examples`、`locales`)に、`make_release.py` は `tools/` に移りました。起動スクリプトは製品フォルダに残り、`python -m github_actions_monitor`(完全版)または `python -m github_actions_monitor.lite`(lite 版)を実行します。アドレスもポートも同じです。利用者のデータ(`actions_monitor.json`、キャッシュ、ログ、`accounts/`、カタログ)は引き続き起動スクリプトの隣にあり、`src/` の中には入りません。

- ガイドのコマンド(`python read_report.py`、`python actions_monitor.py --doctor`、`python monitor_cli.py status` など)はそのまま動きます。同じ名前の小さな入口ファイルが製品フォルダに残るため、パスで登録済みのフックや MCP サーバーも動き続けます。リリースの zip はフォルダ名を保ち、新たに `src/`、`assets/`、`tools/` を含みます。

### 追加

- 平らなインストールだったフォルダ向けの `tools/migrate_layout.py`:既定はドライラン。`--apply` で設定を `layout_backup_<日時>/config/` にコピーし、古いモジュール・ページ・サンプル・`locales/` を `layout_backup_<日時>/old_code/` に移動します(削除も上書きもしません)。そうした残りがある間は `--doctor` が知らせます。`MIGRATING.md` に 8 言語で説明があります。

### セキュリティ

- **GitHub のアドレスがクリーナーを通るのは、決まった形の一覧に合う場合だけです**(リポジトリ、ジョブまたは試行を含む実行、コミット、Issue、プルリクエスト、ファイル)。英数字、ピリオド、ハイフン、アンダースコア、スラッシュ以外の最初の文字で切られ、その後ろは他の文章と同じように消去されます。これまでは、リンクにくっついた秘密(エンコードされたクエリ、カンマ区切りの一覧、コロン、パスの不透明な部分、アドレスの中で始まるメール)がそのまま AI に届いていました。

- **AI クライアントのフックはログの文章を一切渡しません**。渡すのは各アラートのリポジトリ、ワークフロー、結論、リンクだけです。言われる前に行動せよという指示は削除され、最後の行は、ログには第三者が書いた文章が含まれることがあり、それは信頼できないデータであり、そこにある指示には決して従わない、と伝えます。8言語対応。

### 修正

- **AI 向けのイベントストリームが通常のログ行で止まらなくなりました**。フィードの行は、書き込み済みの JSON を消去するのではなく、フィールドごとに消去してから書き出します(原因が `password: x`、`token=x`、`DB_PASSWORD=x` で終わると壊れていました)。消去できない行はスキップしてストリームは続行し、MCP サーバーの応答も同じ方法で消去されます。クリーナーでは `キー=値` の値は引用符、カンマ、セミコロンで終わり、引用符で囲まれた値は全体が消去されます。

- **ヘルプは変更のたびに検査されます**:8 言語のラベルとヘルプがない設定、ヘルプのトピックがないタブ、ヘルプやガイドにない設定やエンドポイントを挙げる変更履歴の行は、テストを失敗させます。ヘルプのチェックリストは CONTRIBUTING とプルリクエストのテンプレートにあります。
- **設定に「クォータ」タブ**(8 言語、lite 版にも):モード、節約モードの値(`modes.*`)、節約(`cache.etag.enabled` と併用するエイリアス `network.etag`)、中央パネル、GitHub App、読み取り用の 2 つ目のアカウントを 1 か所にまとめ、各ソースのクォータと更新時刻を表示し、App と 2 つ目のアカウントをテストし、App に不足している権限を一覧し、推奨値または既定値を適用するボタンを備えます。
- **読み取り用の 2 つ目の読み取り専用アカウント**(`extra_reader.enabled`、`extra_reader.file`):設定にはファイングレイン トークンを含むファイルの**パスだけ**が入り、モニターは使用時に読み取ってメモリに保持し、保存・表示・記録は一切しません。読み取りは各ソースの残り回数に応じてあなたのログイン、App、2 つ目のアカウントに分散され、拒否されたソースは 5 分間除外されて次のソースでやり直し、書き込みとアクションでは使いません。
- **読み取りの集計**:状態、ブリーフ、データに、行われた条件付き呼び出しの数と 304 を返した数(クォータ消費なし)、各ソースのクォータが含まれます。
- **クォータを誰が消費しているか**:モニターは各 1 時間の区間で、アカウント全体の消費量と自身の呼び出し数を比較し、他のツールがどれだけ消費しているかを「クォータ」タブ、状態、ブリーフに表示し、大半を消費している場合は警告します(どのツールかは GitHub からは分かりません)。
- **ストリームはその他のシグナルも運びます**:クォータ切れ、接続の切断、データの陳腐化、中央パネルの遅延、健全性の警告が、現れたとき・変化したとき・解決したときにフィード(およびストリームとフック)のイベントになります。赤いワークフローとセンチネルのパネルだけではありません。
- **バッチのディスパッチは見つけた実行の試行回数を保持します**(バッチ記録の `run_attempt`、`gh run list` の `attempt` フィールドから。`gh` が返さない場合は空)。AI ツール接続とクォータのガイドに、読み取り専用の 2 つ目のアカウントの説明を追加しました。

### 変更

- **同じ行のタイルは同じ高さ**になります(小さな文字が必要とする量に関係なく)。

### 修正

- **未解決の失敗の数値を一本化**:「main の赤」タイル、アラート一覧、下部バー、ブリーフはすべて、既定ブランチの最後の実行が失敗したワークフローを同じ基準で数えます(作業ブランチの失敗はもう未解決アラートとして表示されません)。アラートが開いている間、バーが「通知なし」と表示することはありません。
- **起動時にバージョンを 1 回だけ表示**:見出しを繰り返していた「GitHub Actions v...」の行を削除し、作者とライセンスは 1 行にまとめました。
- **破損した状態ファイル**(形式の違うコラボ状態、センチネルのキャッシュと履歴)は、読み込むコードに届く前にエントリー単位で無視されます。
- **GitHub のクォータ切れはリポジトリごとのエラーではなく 1 件の通知に**:リポジトリの読み取りは更新まで停止し(自動で再開)、アラート一覧と下部バーに「GitHub のクォータは HH:MM まで使い切り ...(未更新のリポジトリ N 件)」と表示されます。赤にはならず、フィード、サウンド、ブリーフにも失敗として届きません。`gh` のエラー文は 1 行に切り詰められ(法的な段落とリクエスト ID なし)、同種のエラーが多数のリポジトリで出た場合は 1 行にまとめられます。
- **「このアプリについて」(およびすべてのページ)がネットワークを待たなくなりました**:モニターの新バージョンの確認は、結果が 1 日以上前の場合に /api/about のリクエスト内で読み取られていたため、ログインなしの `gh` や遅いネットワークでは「このアプリについて」ウィンドウが 10〜25 秒かかっていました。現在はキャッシュの結果を即座に返し、読み取りはバックグラウンドのスレッドが 1 つずつ行います。

## [1.7.6]

モニターと AI ツールの連携: フィードは常にページと一致し、各アラートが赤い理由を示し、ストリームと 3 つの MCP ツールが新着を伝え、コマンド 1 つで連携スクリプトを導入でき、下部のバーが AI の接続状況を示し、すべての状態ファイルは所有者だけが読めます。

### 追加

- **概要とフィードがアラートタブの更新ごとに追従します** (フィードの読み取りごと、各サイクルごとにも): 以前は 1 サイクル遅れていたため、ページが 6 件を示すときに AI が 10 件を読むことがありました。`ALERTS_BRIEF.md` にはお使いのタイムゾーンの `Updated:` と機械向けの行 `updated_epoch:` が入り、`GET /api/ai/brief?fmt=json` は `updated`、`updated_local`、`age_seconds` を追加します。データがまだ読み込まれていないサイクルがアラートを解決することはありません。
- **`ai_alerts.diagnose`** (既定はオフ、設定タブ、8 言語): 新しい赤い実行の各アラートは `diagnosis` を持ちます。最初に失敗したステップとログの関連する約 10 行で、読み取り専用の呼び出しで取得し、シークレットを除去し、サイズとサイクルあたりの実行数を制限します。ログにインフラのエラーがあればアラートは一時的として扱われます。
- **`ai_alerts.cascade`**: 別のリポジトリが赤いために赤くなったアラート (ログまたは規則 `ai_alerts.cascade.map` で名指しされたもの) は、概要でそのリポジトリの下に並び、`origin` を持ちます。
- **`GET /api/ai/stream`** (`ai_alerts.stream`、既定はオフ): サーバー送信イベント、読み取り専用、ネットワークモードではアクセストークンが必要、接続数と時間を制限、`Last-Event-ID` で再開可能。lite 版にはありません。
- **MCP ツール `alerts_open`、`alert_diagnose`、`alert_ack`** (最後のものは `--allow-ack` のときだけ)。AI が接続したとき、`instructions` と通知 1 件で、実際のアラートの件数を伝えます。
- **`monitor_cli.py ai-hook install|status|uninstall [--assistant|--cursor|--generic] [--scope project|user] [--dry-run]`** と連携スクリプト `ai_hook.py` (標準ライブラリのみ): 概要を AI セッションに加え、`ai_alerts.client_hook.block_on_stop` (既定はオフ) のときだけ、ターンの終了前に開いている実際のアラートを確認するよう AI に促します。ツールの設定は置き換えではなくマージされ、ファイルのコピーが保存され、有効な JSON でないファイルは触らずに拒否され、書き込まれる内容はすべて純粋な ASCII です。値は `ai_alerts.client_hook` にあります (設定タブ、8 言語)。
- **AI のハートビート** (`ai_alerts.heartbeat`): ストリーム、MCP サーバー、連携スクリプト、エンドポイントが最後の読み取りを小さなローカルファイルに記録し、下部のバーが AI の接続状況と最後に読んでからの時間を示します。
- **`monitor_cli.py --token-file FILE`**、そして `--token` を使ったとき (プロセス一覧に表示されます) やトークンファイルが他のユーザーに読めるときの stderr の警告。
- すべての変更のテスト (一時フォルダー内、オフライン)。ゆるい `umask` での各状態ファイルのモードの確認を含みます。

### 変更

- **モニターのすべての状態ファイルがモード 0600 で作成されます** (作成するフォルダーは 0700)。単一のヘルパー `private_io.py` を通じて、サイレンス、イベント、フィード、概要、キャッシュ、設定、連携スクリプトのインストーラーが書くファイルが対象です。Windows ではプログラムがモードを強制できません (フォルダーは親の権限を継承します)。
- **`listen.query_access` がまだオンのままネットワークモードを起動すると**、最初の手順 (オフにする、HTTPS か VPN を使う) を表示するようになり、`listen.network` のヘルプと詳細ガイドも 8 言語で同じことを説明します。
- **AI 向けアラートフィードは既定でオフになりました** (`ai_alerts.enabled`、以前はオン): 新しいインストールでは、オンにするまでフィードを書き出しません。フォルダーにすでにフィードがあるインストールはオンのままで、起動時にコンソールが一度だけそれを伝えるため、意図して使っていた人が無効になることはありません。


### セキュリティ

- **送信する通知は環境のプロキシ変数 (`http_proxy`、`https_proxy`) を無視します**: プロキシがあると検査が宛先ではなくプロキシのアドレスを判定してしまい、リダイレクトで応答するプロキシがリクエストをローカルネットワーク (クラウドのメタデータアドレスを含む) に向けられました。新しい設定 `network.use_proxy` (既定はオフ、設定タブ、8 言語) でプロキシを再び使えますが、その場合はプロキシに何かを渡す前に宛先とすべてのリダイレクト先を検査します。メタデータアドレスへリダイレクトするプロキシでテスト済みです。
- **`/api/ai/actions/confirm`、`/api/ai/actions/unlock`、`/api/ai/test`、`/api/notify/test` は、ネットワークモードではこのコンピューターからのみ**使えます (403 `local_only`)。操作を行う他のエンドポイントと同じです。
- **`act` のプランはワークフローに結び付けられます**: プランは解決済みのパスとファイルの SHA-256 を保持し、`act` を起動する直前に再確認します。確認後に編集・置換・削除されたワークフローは実行されません (`workflow_changed`、8 言語の文言つき)。
- **macOS のキーチェーンにトークンをコマンドラインで渡さなくなりました**: `security -i` が標準入力からコマンドを読むため、トークンはプロセス一覧に現れません。
- **`gh` が出力するものはすべて保存前に浄化されます**: AI 向けアクションのログと拒否されたアクションの詳細は浄化処理を通り、古い 40 桁 16 進トークンとモニターが保持するトークンも対象になりました。
- **拒否アドレスの一覧に上限を設けました** (`localguard`): 次のロック時に、問い合わせたアドレスだけでなく期限切れのロックをすべて除去し、2000 件を超えて保持しません。
- **保存できなかったサイレンスは保存済みと報告されません**: ファイルに書けないとき、`POST /api/alerts/mute` と `unmute` は `ok: false` を返します。
- **形の違う応答でもコマンドラインはトレースバックを表示しません**: オブジェクトの代わりのリスト・`null`・数値、または型の違うフィールドは、終了コード 4 とメッセージで終わります。
- **ネットワークのクライアントが書き込める設定は短い許可リストだけです** (言語、タイムゾーン、ページの更新間隔): すべての通知チャンネル、すべてのパス、すべての環境変数名、署名・送信フローが信頼するファイルは、モニターのあるコンピューターから変更します。後から追加された設定は、意図して登録するまでローカル専用です。
- **同じマシン上のリバースプロキシの背後では**、転送ヘッダー (`Forwarded`、`X-Forwarded-*`、`X-Real-IP`) またはプロキシの公開名を持つリクエストは「このコンピューター」とは見なされません。アクセストークンはアドレスごとのロックより先に判定されるため、誤ったトークンの連続でオーナーが締め出されることはありません。
- **このコンピューターへの呼び出しは環境のプロキシを通りません** (`netguard.local_open`。コマンドライン、MCP サーバー、ターミナル表示、フックで使用)。コマンドラインはリダイレクトを追わないため、アクセストークンが別のアドレスに送られません。
- **すべての応答がフレーム埋め込みを禁止します** (`X-Frame-Options: DENY`、`frame-ancestors 'none'`、`nosniff`)。ページは API と同様に `Host` を検査し、非推奨の `?access=` アドレスで認証された応答には `Deprecation` ヘッダーが付きます。
- **ディスパッチと署名**: ディスパッチ前に存在する実行を記録し、新しい実行だけを自分のものと見なします (時計は使いません)。新しい候補が 2 つあれば確認が必要です。入力 `ref` は検査したコミットです。必須ワークフローは表示名ではなくファイルで照合し、バッチ名は UTC です。
- **AI 向けフィードの浄化がより多くの形式に対応しました**: `PASSWORD`、`PWD`、`SECRET`、`TOKEN` で終わる名前、アドレス内の認証情報、Slack と Discord の Webhook、Telegram ボットトークン、`glpat-`・`npm_`・`pypi-` トークン、秘密鍵、長い 16 進文字列、このモニターのアクセストークン。MCP サーバーの `get_run_failure` は、モニターが監視するリポジトリ (または `ai.allowed_repos`) だけを読みます。
- **手で編集したファイル** (サイレンス、更新状態) は不正なエントリだけが失われ、不正な更新状態で起動が止まることはなくなりました。
- **タイムゾーン**: 内蔵テーブルのカイロは 2023 年以降の夏時間に従い、システムが知らないゾーン名は設定タブで拒否されます。完全版は lite 版と同様にヘッダーの赤いワークフロー数を報告し、データのない `monitor_cli.py status` は `health` と同じく終了コード 4 で終わります。

## [1.7.5]

コマンドラインがアクセストークンを専用の名前で受け取り、ネットワークモードは既定でより安全になり（コンピューターのアドレスをネットワークから隠す、古い ?access= アドレスを無効にできる、ローカルネットワーク上の通知先を拒否、平文 HTTP の警告）、人向けの時刻はお使いのタイムゾーンを使い、アラートは項目が変わるまでミュートでき、誤った答えを出していた件数とチェックを修正しました。

### 追加

- **`monitor_cli.py --token TOKEN`**。コマンドラインのアクセストークンは、モニター自身が読む名前になりました。`MONITOR_ACCESS_TOKEN`、その別名 `MONITOR_TOKEN`、`--token` の順です(オプションはプロセス一覧に表示されるため最後の手段です)。拒否されたクライアントのメッセージは変数名を示します。ヘッダーを要求する偽のモニターに対してテスト済みです。
- **stderr の警告**。`monitor_cli.py` が別のコンピューターの暗号化されていない `http` を指すとき(トークンと応答が平文で送られるため)に出ます。応答と `--json` には影響しません。
- **`listen.query_access`**(既定でオン、設定タブ、8 言語)。オフにすると非推奨の `?access=` アドレスは拒否され、セッションは `POST /api/access`(本文のトークン)またはヘッダーでのみ開きます。動作するアドレスは `Deprecation` ヘッダーで応答し、コンソールが非推奨だと表示します。
- **「項目が変わるまで」のミュート**。`POST /api/alerts/mute` は 1 件のアラートに `until_change` を受け付けます。issue またはプルリクエストの `updated_at` を記憶し、それが変わった時点(新しいコメントやプッシュ)または指定時間の終了時の、早い方で終わります。Collab のアラートは `details.updated` を持つようになりました。
- **複数のアカウントで共有されている 1 つのトークンに対する doctor のチェック**(`credential`)。アカウントが GitHub を読むトークン(モニターが保管するトークン、または環境の `GH_TOKEN` / `GITHUB_TOKEN`)の短いフィンガープリントだけを比較し、共有しているアカウントを列挙します。トークン自体は表示されません。
- 各変更のテスト。Webhook の衛生テストを含みます。秘密、メールアドレス、コミットメッセージ、トークンを含むペイロードは、ライブ一覧にも、フィードにも、通知にも届かず、ライブ一覧は許可フィールドの一覧でフィルターされるようになりました。

- **`notify.allow_private_targets`**(既定ではオフ、設定タブ、8言語): ループバック、プライベート(10.x、172.16-31.x、192.168.x、fc00::/7)、リンクローカル(クラウドのメタデータアドレスを含む169.254.x、fe80::/10)、共有(100.64.0.0/10)、予約済みのアドレスである、またはそこに名前解決される通知先は拒否されます。名前は一度だけ解決され、確認済みのアドレスへソケットが開かれ(応答を変える名前は通れません)、すべてのリダイレクトも同じ規則を通ります。`mqtt` と `http_local` は定義上ローカル専用のままです。偽のサーバーと偽のリゾルバーでテスト済み。
- **ネットワークモードでの平文 HTTP への警告**: スイッチ `listen.network` のヘルプが、HTTPS がないとトークンとデータが暗号化されずに流れることを8言語で示します。証明書なしでネットワークで起動すると、コンソールもすでに警告します。
- **人が読む時刻を自分のタイムゾーンで表示**：`monitor_cli.py` の `Last read` 行とミュート、ログ `actions_monitor_log.txt`、番人のレポート、AI 向けの要約、通知は、これまで UTC（`...Z`）をそうと断らずに表示しており、壁の時計と 1〜2 時間ずれていました。今後は `11:43:07 CET (10:43:07 UTC)` のように、コンピューターのゾーン、その名前、隣に UTC 時刻が表示されます。夏時間にも対応します（年 2 回の切り替え前後と、マドリード・UTC・東京・ニューヨークでテスト済み）。
- **`display.timezone`**（初期値 `local`、設定タブと 8 言語に対応）：`utc` または `Europe/Madrid` のような IANA 名を指定すると、ページのテキストと時計がそのゾーンで表示されます。環境変数 `MONITOR_TIMEZONE` はファイルより優先されます。システムにタイムゾーンデータベースがない場合（`tzdata` のない Windows）は、主なゾーンの内蔵テーブルを使います。
- **機械向けのフィールドは UTC のまま、読みやすい対のフィールドを追加**：`ci_red.json` とローカルのキュー出力の `generated_local`、`monitor_cli.py status --json` とページのデータの `updated_local`、`ALERTS_BRIEF.md` の `Updated:` 行。ページの時計と下部のバーにはゾーン（`CET`、`JST` など）が表示されます。
- **アラートタブの「変更されるまで」ボタン**：Issue またはプルリクエストのアラートを、その `updated_at` が変わる（新しいコメント、push）まで、最長で通常の時間だけミュートします。ミュートされたアラートには「変更されるまで消音」と表示されます。8 言語のテキストと回帰テスト付き。

### 変更

### 修正

- **閉じられるかもしれない issue**(サーフェスチェック): 別のワークフローの成功した実行では issue を閉じる提案をしなくなりました。issue はワークフローを名前またはファイル名(`firmware-build.yml` なら「Firmware build failed」)で示す必要があり、同じワークフローが既定ブランチでその後に成功している必要があります。ワークフローを示さない issue は何も提案しません。

- **実行中と待機中のランを一度だけ数えるようにしました**: 「実行中」「待機中」のタイル、「今起きていること」の一覧、ステータスバー(新しい項目「実行中 N · 待機中 M」、`/api/statusbar` の `runs` にも)、`monitor_cli status` が、同じデータなら両エディションで同じ数を示します。ページのフィルタ(エコシステム、状態、検索、タイルからの一覧)でランが隠れる場合、タイルは「13 件中 3 件」を示し、一覧は「14 件中 3 件を表示(フィルタ有効)」で始まるため、ブラウザに保存されたフィルタが不整合に見えることはありません。アクティブなランの一覧は二重に読まれたランも除きます。8 言語のテキストと両エディションのテストを追加しました。

## [1.7.3]

Issue とプルリクエストのための 2 つ目の番人、すべての番人のアラートをまとめた 1 つのタブ、自動で終わるミュート。Collab は読むだけで、ここにあるものは GitHub に何も書き込みません。

### 追加

- **Collab 番人**（`sentinel_collab.py`、完全版のみ、初期状態ではオフ）：リポジトリの未解決の Issue とプルリクエストを、CI 番人に影響しない独自の周期（`sentinels.collab.refresh_seconds`）で確認します。安定したコードを持つ 6 つのルール：`collab.issue.stale`、`collab.issue.critical`、`collab.issue.external`、`collab.pr.review_pending`、`collab.pr.draft_old`、`collab.pr.conflict`。条件付きリクエストで読み（変化のないリポジトリは割り当てを消費しません）、1 回の巡回で最大 `max_repos_per_tick` 個のリポジトリ、`min_rate_remaining` を下回ると停止し、状態は `collab_state.json`（各アカウントのフォルダ内）に保存し、変化だけを通知します。ボットは対象外です。*Issue とプルリクエスト*の層は番人タブにあり、`GET /api/sentinel/collab` が返します。
- **新しいイベント 2 種**、`collab_new` と `collab_fixed`：履歴とすべての通知チャンネル向けです（チャンネルのイベント一覧とイベントスキーマに含まれます）。
- **アラートタブ**（完全版）：すべての番人のアラートを 1 つの一覧にし、由来（CI か Collab）とレベルを表示、由来とレベルで絞り込み、GitHub へのリンク、未解決のエラーがあるときはタブに赤い点を表示します。`?view=alerts&sentinel=collab` で絞り込み済みで開きます。

### セキュリティ

- **緑のコミットには必須の CI が必要です。** `gha_dispatch_all.py` は、必須のワークフローファイルがそのコミットで成功し(既定は `ci.yml`、`dispatch.required_ci`、`dispatch.required_ci_repos`、`dispatch.required_ci_profiles`)、失敗・タイムアウト・承認待ちのものがなく(`action_required` は失敗と同様にブロック)、実行中のものがなく、実行一覧が完全である場合(最大 5 ページを読み、それより長い一覧は緑になりません)にのみ、コミットを緑とみなします。
- **`git fetch` の失敗はそのリポジトリのディスパッチを止めます。** git コマンドには時間制限があり、コミット ID は検証され、古い `origin/main` が証拠として扱われることはありません。
- **カタログはフォルダーの外に出られず、ディスパッチも変更できません。** `tool` はツールフォルダー内にある単純なファイル名でなければならず(外に出るリンクも拒否)、`extra` には `-f key=value` 形式のワークフロー入力だけを入れられ(`dry_run`、`ref`、`-R`、`--ref` は不可)、`finalize_flags` は長いフラグだけで、`gh workflow run` の引数は検証済みの部品から作られ、バッチの実行時に再確認されます。
- **古いバッチは盲目的に署名されません。** `finalize` は、確認したコミットの上に作られたとバッチが記録している実行だけを署名に提示します。古いバージョンが書いたバッチは `needs_review` になり、`finalize --accept-legacy` は GitHub から実行を読み直し、そのコミットが記録と一致する場合にだけ受け入れ、警告し、署名のたびに LEGACY という語を求めます。
- **`act` はワークスペースの外に出ません。** クローンは解決され、ワークスペース内の実在のフォルダーでなければなりません(リンク、`..` を含む名前、別の場所を指す `.github` は拒否。`act.allow_symlinks` はクローンへのリンクを許可します)。時間制限と Stop は、実行が起動したプロセスのツリー全体(Linux と macOS ではプロセスグループ、Windows では自身の PID に対する `taskkill /T`)を終了し、その実行が作った `act-` コンテナーを削除します。
- **ネットワークモード**: 自分の証明書と鍵で直接提供する HTTPS(`listen.tls_cert_file`、`listen.tls_key_file`。TLS 1.2 以上で、使えない場合は平文の HTTP では起動しません)、または HTTPS プロキシの背後での `Secure` クッキー(`listen.secure_cookie`)。アクセストークンはすぐにアドレスバーから消えます(リダイレクト、`Referer` なし)。誤ったトークンを送りすぎたアドレスは 5 分間拒否されます(`listen.max_failed_attempts`)。ページのアドレスはサーバーが待ち受けているものです。受け付けるのは IPv4 アドレスのみで、設定でも検査でも同じです。接続が平文の HTTP のときはコンソールがそう伝えます。
- **Webhook**: 各配信には `X-GitHub-Delivery` の ID が必要で、繰り返された配信は `webhook.replay_seconds` の間無視されます。1 つのリポジトリが 1 分間に引き起こせる受け付け済みイベントは最大 `webhook.max_per_minute` 件です。`full_name` の所有者は監視対象のアカウントでなければなりません。ネットワークモードでは 1 つのアドレスは 1 分あたり 120 リクエストに制限されます。受け付けたイベントはそのリポジトリの保存済み条件付き読み取りを破棄し、次のサイクルの対象にします。異常な文字を含む署名ヘッダーは単に拒否されます。
- **MCP サーバー**: 形式が誤ったメッセージ(パラメーター、引数、id、メソッド)にはそのメッセージだけにエラーを返し、ツールの予期しない不具合は内部エラーとなってもサーバーを終了させず、64 KB を超える行は拒否されます。
- **保存された GitHub トークンは `gh` にだけ渡されます。** モニターの環境には置かれなくなったため、`act`、通知コマンド、その他の子プロセスは継承できません。
- **GET は何も書き込みません。** 監査フォルダーへの日報のコピーは、ワンタイムトークン付きの POST(`/api/sentinel/parte/save`)になり、GET の `?save=1` は廃止されました。
- `--doctor` は危険な組み合わせ(全インターフェースでのネットワークモード、ネットワークモード中に実行する AI アクション、ネットワークモード中の `act`、平文ファイルのトークン)を名指しし、トークンの保存場所を示しますが、トークン自体は決して表示しません。

- 検証できる形式が増えました：HYDRA の `hydra-sign`（`FILE.sig` はファイルのバイト列に対する Ed25519 の base64、固定されたリリース鍵、ブロック単位で読み込み）は確定的に検証されます。URTC の `.imgsig` は厳密な形式（16 進 152 桁 + LF、不正は無効）が検証され、正しい形式なら「unknown」のままです（署名されたメッセージにはビルドヘッダーも必要ですが、署名済みフォルダーにはありません）。ARMOR の APK は APK 内で apksigner により署名され、「unknown」のままです。
- `HYDRA-UMC-OS` は `targets.json` で意図的にラベル付けされました（`"build_only": true` + `reason`）：`plan` は BUILD ONLY の下に一覧し、孤児ではなくなりました。署名ツールには触れていません（そのワークフローは別の入力と別の署名方式を使います）。
- 修正：`ci_red.target_path` が、バックスラッシュで書かれた Windows のパス（`C:\...`）をすべて拒否していました。スラッシュだけが受け入れられていました。

- リリース：ターゲットの種類ごとの期待されるアセット（不完全に公開されたときにアラート）、タグとマニフェストと CHANGELOG の比較、GitHub Packages、忘れられた下書きとプレリリース、`release_notes.py`（最後のタグ以降のコミットからリリースノートの下書きを作成。何も公開しません）。
- セキュリティ：経過日数別の重大／高アラートとリポジトリのランキング、カバレッジ（CodeQL / Dependabot のないスタック）、シークレットスキャンの未解決と解決済み、優先度別の Dependabot（ランタイムのメジャーが先、CI のみが最後）。
- Issue と PR：CI が再び緑になったビルド Issue への `gh issue close` の提案（テキスト付きのイベント。何もクローズしません）、期限切れのマイルストーン、古い人間の PR、ワークフローや CODEOWNERS に触れる PR、マージキュー（チェックが緑で承認済み）。古いボードカード：保留（項目ごとの読み取りとしきい値が必要）。
- マニフェストと証拠の比較（成熟度）、8 言語の README の整合性の失敗、ヘッダー・レポート・A7 でのエコシステムごとの Actions の分数。
- `finalize --execute` は、実行中のモニター（127.0.0.1）に、署名したリポジトリだけを更新して `ci_red.json` をすぐに書き直すよう伝えます（`monitor_link.py`）。
- 任意の署名付き Webhook 受信（`webhook.enabled`、既定はオフ、127.0.0.1 のみ、設定の共有シークレットによる HMAC、GitHub トークンは使いません）。
- コスト：ホットな周期には何もありません。コールドで、周期に分散し、時間あたりの予算内で：リポジトリあたり 1 日 2 回の REST 呼び出し、15 リポジトリあたり 1 日 1 回の GraphQL クエリ、Packages に 3 回、さらに赤い実行のジョブと署名キューの証明書の問い合わせ。割り当てが `min_rate_remaining` の 2 倍を超えているときのみです。ホットな GraphQL パスはノードごとに 3 つのフィールド（アラートの日付、レビューの判定、チェックの状態）を追加で取得します：追加の呼び出しはありません。

## [1.0.0]

最初の番号付きバージョン。パッケージの機能：

- 4 つのエコシステムのための GitHub Actions モニター（ローカルの Web ページ、実行のキャッシュ、止まったビルド、build-failed / build-stuck の Issue）。
- 番人の層 A（読み取り専用、AI 不要）：A1 止まったビルド、A2 赤い CI（唯一の基準：各ワークフローの既定ブランチでの最後に完了した実行）、A3 CodeQL / Dependabot / シークレットのアラート、A4 Dependabot のプルリクエスト、A5 リリース（候補、リリースのない緑のビルド、署名待ち）、A6 衛生、A7 消費（分数と API の割り当て）、A8 監査とラウンド、A9 ロードマップボード。
- 各ビルド対象の明示的な状態：built_on_gha -> signed_local（none | dev | release）-> published。`last_build_at`、`last_signed_at`、`signature_kind`、実際の待ち時間を持ち、ローカルのバッチと署名済みフォルダーの記録は、GitHub を待たずに署名待ちアラートを下げます。
- 当日の署名キュー（`a5.sign_queue`）：最も緊急なものから、各対象の正確な finalize コマンド付き。
- エコシステムごとの Actions の分数の予算（`sentinel.minutes_budget`、既定は空）：80 % でレポートとイベントに警告。
- イベントフィード（`events_monitor.jsonl`）と `ci_red.json`（リポジトリ -> 赤いワークフロー + 署名待ちの時間）。アトミックに書き込まれます。
- バッチツール：`gha_dispatch_all.py plan|dispatch|status|finalize|hygiene`（`--only` または `--ecosystem`）、`plan --json`、`finalize --json`、バッチの最後に失敗した dispatch を 1 回再試行、ターゲットは `targets.json` のデータ。
- `read_report.py`：実行中のモニターから、API の割り当てを使わずにプレーンテキストのレポートを取得。
- `make_release.py`：品質ゲート（ユニットテスト、クリーンな zip、完全なサンプル設定、バージョンと変更履歴の一致）と SHA256SUMS。

このバージョンでは未対応：リリース署名の公開鍵による検証と、番人からのビルドの証明書（エコシステムごとに署名形式が異なり、証明書にはネットワークが必要で、署名ツールが公開前に両方を検証します）。

# 监视器能节省什么:估算与测量方法

本指南解释 README 中的数字。它们是用简单模型得出的估算,不是在你的仓库上测得的结果。在依赖它们之前,请先测量你自己的情况。

## 数字

- 监视 CI 和分诊失败所花时间的约 85-95 %。
- 团队整体生产力的约 15-25 %,是第一个数字带来的结果。

## 估算是如何得出的

一周节省的时间 = 对各项任务求和:(每周次数 x 没有监视器时每次所需分钟数)x 该任务的节省比例。任务包括:监视每个工作流、判断什么才是真正的红色、查找失败运行的原因、及时得知失败。该估算假设:

1. 有许多仓库,每个仓库有多个工作流,因此手动查看意味着反复打开许多页面。
2. 没有监视器时,有人手动检查 Actions 标签页,并逐个阅读失败日志来查找原因。有了监视器,页面和警报已经说明哪个工作流为红以及原因。
3. 每周都会出现失败。没有失败的团队无需分诊。
4. 节省只涵盖监视和分诊。修复失败所需的时间无论有没有监视器都一样,不计入其中。

只有当监视和分诊约占团队工作时间的 16-29 % 时(0.15 / 0.95 到 0.25 / 0.85),两个数字才一致。如果你的团队占用更少,整体收益就更低。

## 什么时候节省更少

- 仓库很少或只有一个工作流:需要监视的内容很少。
- 目前没有人手动监视 CI,或者你已经有指明原因的警报。
- 警报没有被阅读。阅读也需要时间,如果无故忽略或静音,节省就会消失。

## 如何在自己的使用中测量

1. 之前:在正常的一周里,记录每次手动查看 CI 的分钟数,以及每次分诊失败运行直到知道原因的分钟数。
2. 之后:打开监视器再用一周,做同样的记录。评分(恢复时间)和失败记录簿(24 小时和 7 天的趋势)显示失败是否更快被解决。
3. 对每一组,节省比例为 1 - 之后 / 之前。与 85-95 % 比较。
4. 整体收益为节省的小时数除以该周的总工作小时数。与 15-25 % 比较。

### 使用虚构数字的示例

某人每天花 20 分钟查看 Actions 标签页(五天工作周共 100 分钟),每周分诊 4 个失败运行,每个 30 分钟(120 分钟):共 220 分钟。节省 85-95 %,可腾出 187 到 209 分钟。这些数字是为演示计算而虚构的,请使用你自己的数字。


## 在监控器中测量

页面可以用你自己的记录替你完成本指南中的计算:开启 `productivity.enabled`(设置的分析),并在那里写下“之前”和“之后”的记录。分析部分随后会逐项任务显示每周节省分钟数的估算。对于你没有记录“之前”的任务,显示 **无数据**;凡是来自本指南百分比而不是你自己“之后”记录的节省,都标注为 **假设(未测量)**;85-95 % 或 15-25 % 绝不会被当作测量值显示。参见 [ANALYTICS_zho.md](ANALYTICS_zho.md)。

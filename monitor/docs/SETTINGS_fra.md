# L'onglet Paramètres

L'onglet Paramètres (l'entrée Paramètres du panneau latéral) modifie depuis la page les valeurs de `actions_monitor.json`, afin que personne n'ait à éditer le fichier à la main.
Il est rédigé dans les huit langues de la page et suit l'apparence du reste.

<!-- settings:begin -->
## Ce qui peut être modifié

Seulement les clés de la liste de `settings_api.py` (le schéma). Chacune a un type et une plage, et la page indique si un changement demande un **redémarrage** du moniteur (la boucle lit sa configuration une fois) ou **s'applique tout de suite**.

L'onglet est divisé en sous-onglets, du plus courant au plus avancé : Ce navigateur, Essentiel, Général, Actualisation et limites, Sentinelle, Contrôles de surface (A10), Préparation (A11), Dossiers et fichiers, Sorties, puis les intégrations. Dans un sous-onglet, les réglages sont regroupés en blocs titrés ; le premier champ d'un bloc est son interrupteur principal et, tant qu'il est éteint, le reste du bloc est atténué et non modifiable. Chaque champ affiche son unité (s, min, h, jours, Mo, appels), sa plage, un badge (demande un redémarrage / s'applique tout de suite), un badge pour les options de sécurité qui démarrent à leur valeur prudente et une ligne d'aide. La recherche filtre les réglages de tous les sous-onglets ; chaque sous-onglet compte ses modifications non enregistrées ; les boutons Enregistrer et Annuler restent visibles ; le navigateur retient le dernier sous-onglet. Les onglets suivent le schéma clavier des onglets (flèches, Début, Fin).

Un réglage n'apparaît qu'à un seul endroit. Lecture seule : `webhook.signing_state` indique seulement si le secret partagé est défini ; le secret lui-même n'est jamais affiché.

Quels dépôts sont surveillés : le catalogue d'exemple des écosystèmes se termine par un groupe `rest` (préfixe `*`, « Everything else ») qui prend tout dépôt qu'aucun autre groupe ne réclame, donc rien n'est laissé de côté par défaut. Si votre propre catalogue en laisse, un bandeau de la page dit combien (« votre filtre d'écosystèmes masque N des M dépôts du compte »).

IA externe : `ai.provider` peut valoir `ollama` (cet ordinateur), `openai-compatible` (tout point d'accès de style OpenAI, qui sert aussi pour Gemini via son point d'accès compatible OpenAI et pour OpenAI), `anthropic` (l'API Messages ; vous choisissez le modèle) ou `copilot` (`gh copilot` avec votre connexion ; consomme des requêtes premium). La clé n'est jamais enregistrée : seulement le NOM de la variable d'environnement. Voir AI_fra.md.

### Exemple de sources d'épinglage

Les versions épinglées ne sont lues que si une source est indiquée ; avec une liste vide rien n'est lu et la page le dit. Le texte suivant est un exemple, commenté :

```jsonc
// Example, commented out: where the pinned versions of an ecosystem live. Copy the part you need into
// "sentinel" > "readiness" > "pins" > "sources" of actions_monitor.json (or paste it in the Settings tab) and remove the comments.
// [
//   {"ecosystem": "alpha", "kind": "pin_table", "provider": "ALPHA-COMMON", "file": "pins/consumers.json", "key": "consumers"},
//   {"ecosystem": "beta",  "kind": "lock_files", "provider": "BETA-CORE", "lock_name": "beta.lock.json", "version_key": "core"}
// ]
// pin_table: a JSON file of the provider that maps each repository to the version it pins (under "key").
// lock_files: every clone is searched (down to "max_depth" folder levels) for files called "lock_name"; the OLDEST version found in "version_key" counts.
```

## Ce qui ne peut jamais être modifié ni consulté depuis la page

Jetons, secrets, clés de signature, secret du webhook, commande que la sentinelle peut exécuter (`sentinel.notify_command`), clé d'API de l'IA (seul le nom de sa variable d'environnement peut être défini) et toute clé d'un autre outil : ils ne figurent **pas dans le
schéma**, donc la page ne les affiche ni ne les écrit, et une requête qui en nomme un est refusée. Toutes les autres clés du fichier sont conservées exactement telles qu'elles étaient.

## Comment se déroule un enregistrement

1. Seules les valeurs modifiées sont envoyées, sous la forme `POST /api/settings` avec `Content-Type: application/json` et un corps de 16 Ko au maximum.
2. Chaque valeur est vérifiée selon son type et sa plage ; une seule valeur invalide fait refuser toute la requête et rien n'est écrit. Les chemins doivent être du texte sans caractères de contrôle, jamais un
   chemin réseau (UNC) et jamais sur le lecteur `D:`.
3. Le fichier précédent est copié vers `config_backups/actions_monitor-<time>.json` (les dix dernières copies sont conservées).
4. Le nouveau fichier est écrit dans un fichier temporaire puis déplacé par-dessus l'ancien (de façon atomique), si bien qu'un plantage ne laisse jamais un fichier à moitié écrit. Un fichier qui n'est pas du JSON valide n'est jamais écrasé depuis la page.
5. La page indique quelles valeurs enregistrées nécessitent un redémarrage et conserve un bandeau jusqu'à ce que vous redémarriez.

## Qui peut effectuer la requête

Uniquement la page de la même machine : le serveur écoute sur `127.0.0.1` et refuse toute requête dont l'en-tête `Host` ou `Origin` n'est pas sa propre adresse (les mêmes contrôles que pour tous les autres points d'accès).
Un formulaire provenant d'un autre site ne peut pas l'atteindre, car la requête doit être au format JSON.

## Avant la 1.5.0

La langue des outils était déterminée par la langue du système ; désormais ils démarrent en anglais et la langue est un paramètre (ici `language`, `MONITOR_LANG` ou `--lang`).
`parte_history_days` s'appelle désormais `report_history_days` (l'ancien nom est toujours lu).

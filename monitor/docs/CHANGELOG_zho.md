# 更新日志

工具本身(监视器 + 哨兵 + 批处理工具)的版本,采用自己的语义化版本号。源文件是英文的 CHANGELOG.md,本文件包含相同的版本和章节。

## [Unreleased]

1.7.4 之后正在进行的工作。

### 新增

- **`monitor_cli.py --token TOKEN`**,命令行的访问令牌现在使用监视器自己读取的名称:先是 `MONITOR_ACCESS_TOKEN`,再是其别名 `MONITOR_TOKEN`,最后是 `--token`(命令行选项会出现在进程列表中,因此是最后手段)。被拒绝客户端的消息会指出变量名。已针对要求该请求头的模拟监视器测试。
- **stderr 警告**:当 `monitor_cli.py` 指向另一台计算机的未加密 `http` 时(令牌和响应将以明文传输)会打印警告;响应和 `--json` 不受影响。
- **`listen.query_access`**(默认开启,位于设置页,八种语言):关闭后,已弃用的 `?access=` 地址会被拒绝,会话只能通过 `POST /api/access`(正文中的令牌)或请求头打开。仍可用的地址会以 `Deprecation` 响应头回应,控制台会说明它已弃用。
- **“直到该项目发生变化”的静音**:`POST /api/alerts/mute` 对单条警报接受 `until_change`;静音会记住 issue 或拉取请求当时的 `updated_at`,当它变化(新评论、推送)或小时数结束时(以先到者为准)立即结束。Collab 的警报现在带有 `details.updated`。
- **针对多个账户共用同一令牌的 doctor 检查**(`credential`):只比较各账户读取 GitHub 所用令牌的简短指纹(监视器保存的令牌,或环境中的 `GH_TOKEN` / `GITHUB_TOKEN`),并列出共用同一令牌的账户;绝不显示令牌本身。
- 每项改动都有测试,包括一个 webhook 卫生测试:带有密钥、电子邮件、提交信息和令牌的载荷不会到达实时列表、动态流或通知,实时列表现在由允许字段列表过滤。

- **`notify.allow_private_targets`**(默认关闭,在“设置”标签页,八种语言):拒绝属于或解析到回环、私有(10.x、172.16-31.x、192.168.x、fc00::/7)、链路本地(169.254.x,含云元数据地址,fe80::/10)、共享(100.64.0.0/10)或保留地址的通知目标。名称只解析一次,套接字连接到已检查的地址(改变应答的名称无法通过),每次重定向也遵循同一规则。`mqtt` 和 `http_local` 按定义仍仅限本机。已用假服务器和假解析器测试。
- **网络模式下纯 HTTP 的警告**:开关 `listen.network` 的帮助现在以八种语言说明,没有 HTTPS 时令牌和数据以明文传输;在没有证书的情况下以网络模式启动时,控制台已会发出警告。
- **为人而写的时间采用您自己的时区**：`monitor_cli.py` 的 `Last read` 行和静音、日志 `actions_monitor_log.txt`、哨兵的报告、给 AI 的摘要以及通知，以前都以 UTC（`...Z`）显示且不加说明，与墙上的时钟相差一两个小时。现在它们显示为 `11:43:07 CET (10:43:07 UTC)`：计算机的时区、其名称，旁边是 UTC 时间。夏令时也会跟随（已围绕一年中的两次切换，并针对马德里、UTC、东京和纽约测试）。
- **`display.timezone`**（默认 `local`，位于“设置”标签页，支持八种语言）：`utc` 或如 `Europe/Madrid` 的 IANA 名称会让页面的文本和时钟按该时区显示；环境变量 `MONITOR_TIMEZONE` 优先于文件。系统没有时区数据库时（没有 `tzdata` 的 Windows），使用内置的常用时区表。
- **面向机器的字段保持 UTC，并新增一个易读的对应字段**：`ci_red.json` 和本地队列导出中的 `generated_local`，`monitor_cli.py status --json` 和页面数据中的 `updated_local`，以及 `ALERTS_BRIEF.md` 中的 `Updated:` 行。页面的时钟和底部栏会显示时区（`CET`、`JST` 等）。
- **“警报”标签页新增“直到发生变化”按钮**：将某个 issue 或拉取请求的警报静音，直到其 `updated_at` 发生变化（新评论、推送），最长为通常的小时数；被静音的警报显示“已静音，直到发生变化”。含八种语言的文本和一个回归测试。

### 变更

- **API 现在把版本称为 `complete`**(以前是 `full`),涉及 `/api/about`、`/api/statusbar`、`--doctor --json` 和命令行;`full` 保留给哨兵可以执行的内容。页面和命令行仍能理解这两个词。
- **静音只能在监视器所在的计算机上进行**(网络模式下同样如此,直到有带用户的版本):Collab 指南用八种语言说明了这一点,并有测试保证该路由受此规则约束。
- **本仓库的工作流使用固定到完整提交的 Action**,版本写在注释中,并有测试保证。

### 修复

- **可以关闭的 issue**(表面检查):另一个工作流的绿色运行不再触发关闭 issue 的建议;issue 必须点出工作流(用名称或文件名,`firmware-build.yml` 对应“Firmware build failed”),并且同一个工作流在默认分支上必须有之后的绿色运行。没有点出任何工作流的 issue 不会给出建议。
- **标签与清单**(表面检查):当最新发布的标签领先于从克隆中读取的清单时,会针对该发布读取一次 GitHub 上默认分支的清单(发布后克隆可能落后),如果它已经是该版本,警告就会消失;不是版本号的标签(`meshes-1`)会被忽略。
- **发布候选的下一步**:发布需要签名构建的仓库现在显示“在 Actions 中构建并签名”,与“提升版本”“签名”“发布”区分开;由别处负责的生态系统的仓库不再算作候选(已测试)。
- **运行中和排队中的运行只统计一次**:“运行中”和“排队”磁贴、“正在发生”列表、状态栏(新增项“运行中 N · 排队 M”,也出现在 `/api/statusbar` 的 `runs` 中)以及 `monitor_cli status` 在两个版本中对相同数据给出相同数字。当页面筛选(生态、状态、搜索、来自磁贴的列表)隐藏了部分运行时,磁贴显示“13 中的 3”,列表以“显示 14 个中的 3 个(筛选已启用)”开头,浏览器中保存的筛选不再看起来像不一致。活动运行列表还会丢弃被读取两次的运行。八种语言的文本以及两个版本的测试。

### 安全

- **在网络模式下,`/api/statusbar` 不再把本机在局域网中的地址(`lan_address`)交给网络客户端**;状态栏在没有它时照常绘制。
- 已弃用的 `?access=` 地址只在 `GET` 时有效。

- **全屏按钮**位于右上角（Fullscreen API；再按一次退出），图标和文字支持八种语言。
- **可排序的表格**：“仓库”和“历史”点击表头即可排序（升序、降序、无），按住 Shift 点击可按多列同时排序（每个排序键显示序号和方向），空值始终排在最后，排序会被记住。列选择器可添加更多列：历史中有运行编号、触发者、短提交、尝试次数、排队等待、文件和生态系统；仓库中有生态系统、运行编号、触发者、提交、尝试次数、排队等待、24 小时运行数、默认分支、可见性、最近推送和未关闭的拉取请求。监视器现在会发送每次运行的编号和排队等待时间，以及每个仓库的一小块信息（取自已读取的内容，不会从 GitHub 读取新数据）。
- **`monitor_cli.py`**，作为运行中监视器客户端的命令行（`status`、`health`（或 `check`）、`doctor`、`accounts`、`alerts`、`live`）：读取本机或 `--url` / `MONITOR_URL` 上的 `GET /api/...`，输出文本，或用 `--json` 输出一个 JSON 文档，支持 `--account`、`--sentinel`、`--level`、`--muted`、`--timeout` 和 `--lang`，并使用稳定的退出码（0 正常，1 用法错误，2 无法连接监视器，3 凭据被拒绝，4 降级，5 通过 `--fail-on` 发现警报）。`health` 能区分监视器无响应、GitHub 登录失败和配额耗尽。精简版支持 `status`、`doctor` 和 `health`。它从不向 GitHub 写入，网络模式的访问令牌放在 `MONITOR_TOKEN` 中。旧的工具仍然可用。八种语言的指南（`CLI.md`）。
- 每项改动都有测试，包括在安装了 Node 的环境中真实运行的排序逻辑、针对模拟监视器的各命令、每个退出码，以及一项测试：每种语言的更新日志都按从新到旧列出版本，且版本与源文件一致。

## [1.7.3]

第二个哨兵，用于 Issue 和拉取请求；一个汇总所有哨兵警报的标签页；以及会自行结束的静音。Collab 只读取，这里没有任何内容会向 GitHub 写入。

### 新增

- **Collab 哨兵**（`sentinel_collab.py`，仅完整版，默认关闭）：按自己的周期（`sentinels.collab.refresh_seconds`）查看你仓库中未关闭的 Issue 和拉取请求，绝不影响 CI 哨兵。六条带稳定代码的规则：`collab.issue.stale`、`collab.issue.critical`、`collab.issue.external`、`collab.pr.review_pending`、`collab.pr.draft_old` 和 `collab.pr.conflict`。它使用条件请求读取（没有变化的仓库不消耗配额），每轮最多 `max_repos_per_tick` 个仓库，配额低于 `min_rate_remaining` 时暂停，状态保存在 `collab_state.json`（位于各账户的文件夹内），只通知变化。机器人不计入。其*Issue 与拉取请求*层位于哨兵标签页，由 `GET /api/sentinel/collab` 提供。
- **两个新事件**，`collab_new` 和 `collab_fixed`，用于事件流和所有通知渠道（已列入渠道的事件列表和事件模式）。
- **“警报”标签页**（完整版）：一个列表汇总所有哨兵的警报，每条标明来源（CI 或 Collab）和级别，可按来源和级别筛选，带 GitHub 链接，并在标签上用红点提示未处理的错误。`?view=alerts&sentinel=collab` 会直接打开已筛选的视图。
- **会结束的静音**（`alert_center.py`）：在“警报”标签页中，可将某个警报、某条规则（其代码）或整个哨兵静音 `alerts.mute_hours` 小时（默认 24，范围 1 到 720）。静音会自行到期，可立即恢复，简短的历史记录显示静音了什么、从何时到何时。这只是监视器的备注，按账户保存在 `alert_mutes.json`，GitHub 上不会有任何变化。
- Collab 规则中的 **`ignore_labels`**（默认 `monitor:ignore`）：由人在 GitHub 上打了该标签的 Issue 或拉取请求不会产生警报。监视器从不写标签。
- **`GET /api/alerts`**（`?sentinel=`、`?level=`、`?muted=show|hide|only`）和 **`GET /api/events`**（`?sentinel=`、`?since=`），均为只读且按账户区分；`POST /api/alerts/mute` 与 `/api/alerts/unmute` 仅限本机，需要一次性令牌，与其他所有变更相同。
- **实时视图中的检查清单**（至少 32 个字符的密钥、转发或隧道到 `/api/webhook`、GitHub 的测试事件、留意配额），Webhook 指南中也有同样的步骤。
- **八种语言的 Collab 哨兵指南**（`COLLAB.md`），可通过帮助找到。
- 每项改动都有测试：规则及其稳定代码、开销（条件读取、每轮上限、暂停）、只读、静音（范围、结束、上下限、历史、损坏的文件）、忽略标签、各端点、精简版没有这些功能、各账户和演示的状态文件，以及八种语言的文本。

### 变更

- 设置页在哨兵标签页的一个区块中有十二项 Collab 设置，旁边是 `alerts.mute_hours`。
- 文件 `alert_mutes.json`、`collab_state.json`、`ai_alerts_state.json` 和 `ALERTS_BRIEF.md` 从不提交，也从不随软件包发布。

## [1.7.2]

按顺序阅读且适应窗口的标题栏、固定在右上角的快捷控制、侧边栏中的“关于”，以及取消新版本通知。测试不再在代码旁留下文件，而正是这一点曾把个人的设置换成了中性模板。

### 更改

- **标题栏的数字按顺序排列并使用网格**（所有版本）：第一行现在从正在发生的事情排到需要关注的事情（运行中、排队、失败、成功、计算分钟、未解决的问题、main 上为红色的工作流、未签名），第二行保留运行机制（仓库、热点、模式、节省的读取、额度、连接、更新时间）。每一行是一个八列的网格，按其自身区块的宽度变为四列或两列，因此在任何窗口宽度下（从 1080p 屏幕起）两行都能排满，磁贴不会强制自己的宽度。较长的额度磁贴占两列。
- **快捷控制固定在右上角**：“仅热点”按钮、速度列表（正常、快速、极速）和各生态系统的健康标签（以及预算和暂停提示）固定在那里，位于独立的一列中，在其内部换行而不会挪动数字。窗口宽度低于 1100 点时，该角落移到数字上方。所有账户的页面会隐藏它，就像隐藏数字一样。
- **设置、帮助和关于只在侧边栏中**：齿轮、问号和信息按钮离开标题栏。设置本来就是侧边栏的一个栏目；“此标签页的帮助”保留在底部，旁边新增了**关于**。设置指南在八种语言中都说明了这一点。

### 移除

- **标题栏中的新版本通知**（橙色徽章）及其代码和样式。“关于”面板和控制台仍会告知是否有更新的版本；设置 `updates.check` 和 24 小时缓存保持不变。

### 修复

- **中性模板可能替换个人的设置。** 三组测试（lite 隔离、一次性令牌，以及账户中的 lite 部分）启动的监视器在首次启动时会在代码旁写入 `actions_monitor.json` 或 `update_check.json`，而没有任何东西把它们删除；把 `monitor/` 文件夹复制到已安装的目录上，个人的设置（自己的生态系统目录）就被模板替换，所有仓库都落入“Everything else”分组（右上角显示“Everything else 54”）。这些测试现在会删除自己创建的文件，并有一个测试加以证明。软件包从未包含任何人的设置或目录，今后也不会包含。

## [1.7.1]

一个新页面，以及放在契约之后的同一个哨兵。页面左侧有侧边栏，包含徽标、分组的栏目和十六个主题；CI 哨兵现在是注册表中的哨兵之一，下一个哨兵正是靠这一点得以加入。监视器显示和判断的内容没有改变。

### 新增

- **侧边栏**（所有版本）：工具的徽标（一个用主题颜色绘制的 SVG，当系统要求减少动效时保持静止）、账户切换器、分成三个可折叠组的栏目（监控、数据、系统）以及帮助。侧边栏可以收起为仅显示图标，两项选择都会记在浏览器中。顶部栏显示栏目名称和工具。方向键（包括上下）可在栏目之间移动。小屏幕上侧边栏移到顶部。`?chrome=0` 会隐藏它，就像过去隐藏标签栏一样。
- **十六个主题**（在自动、浅色和深色之外）：报警系统 Studio 的主题（Armor、Aqua、Midnight、Ember、Forest、Violet、Solar、Ice、Crimson、Mono、High contrast、Metallic、Professional、Videogame、Terminal 和 Blueprint），可在设置 > 此浏览器的列表中选择，或使用 `?theme=`。每个主题定义页面、侧边栏、面板、线条、文字、强调色、圆角和字体。绿、红、琥珀和蓝在所有主题中保持原有含义，在需要时调亮或调暗，使每个数字的对比度都达到 4.5:1 或更高，徽章的文字随其颜色而变。
- **`BaseSentinel`、`Alert` 和 `SentinelRegistry`**（`sentinel_base.py`、`sentinel_registry.py`；仅完整版）：哨兵的契约（`start`、`stop`、`tick`、`get_status`、`get_alerts`、`get_metrics`、`get_config_schema`、`refresh_seconds`）、带有不依赖语言的稳定代码（`ci.red`、`ci.stuck`、`ci.pending_sign`）和所属账户的警报，以及为每个哨兵提供独立时钟的注册表。`actions_monitor.json` 中的 `sentinels.<名称>.enabled` 可开启或关闭其中一个；没有它时仍由 `sentinel.enabled` 决定，两者都有设置时以新的块为准。
- **`SentinelCI`**（`sentinel_ci.py`）：原来的哨兵，放在该契约之后。它持有旧的 `Sentinel`，不改变其判断方式：同样的红色规则（每个工作流在默认分支上最后一次完成的运行）、同样的文件、同样的循环、同样的快照。

- **保存的 GitHub 令牌只交给 `gh`。** 它不再放入监视器的环境中,因此 `act`、你的通知命令和其他子进程都无法继承它。

- 当日签名队列（`a5.sign_queue`）：最紧急的在前，附每个目标确切的 finalize 命令。
- 每个生态系统的 Actions 分钟预算（`sentinel.minutes_budget`，默认为空）：达到 80% 时在报告中警告并产生事件。

- 批处理工具：`gha_dispatch_all.py plan|dispatch|status|finalize|hygiene`，带 `--only` 或 `--ecosystem`、`plan --json`、`finalize --json`，批次结束时对失败的 dispatch 重试一次，目标作为数据保存在 `targets.json` 中。
- `read_report.py`：从运行中的监视器获取纯文本报告，不消耗 API 配额。
- `make_release.py`：质量闸门（单元测试、干净的 zip、完整的示例配置、版本与更新日志一致）和 SHA256SUMS。

此版本未完成：由哨兵根据公钥验证发布签名以及构建证明（各生态系统的签名格式不同；证明需要网络；签名工具在发布前会验证两者）。

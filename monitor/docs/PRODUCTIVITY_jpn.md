# モニターが節約するもの:推定と測り方

このガイドは README の数値を説明します。数値は単純なモデルによる推定であり、あなたのリポジトリで測定したものではありません。信頼する前に、ご自身で測定してください。

## 数値

- CI の監視と失敗の仕分けに使う時間のおよそ 85〜95 %。
- チーム全体の生産性のおよそ 15〜25 %(1 つ目の数値の結果として)。

## 推定の組み立て方

1 週間に節約できる時間 = 各作業について(週あたりの回数 × モニターなしで 1 回にかかる分数)× その作業の節約率 を合計したもの。作業は、全ワークフローの監視、本当に赤いものの判断、失敗した実行の原因調査、失敗に早く気づくこと、の 4 つです。推定は次を前提にしています。

1. 各リポジトリに複数のワークフローがある多数のリポジトリがあり、手作業で見るには多くのページを何度も開く必要がある。
2. モニターがなければ、誰かが Actions タブを手作業で確認し、失敗したログを一つずつ読んで原因を探す。モニターがあれば、ページとアラートがどのワークフローがなぜ赤いかをすでに示す。
3. 失敗は毎週発生する。失敗のないチームには仕分けるものがない。
4. 節約の対象は監視と仕分けだけ。失敗の修正にかかる時間はモニターの有無で変わらず、含まれない。

二つの数値が整合するのは、監視と仕分けがチームの作業時間のおよそ 16〜29 % を占める場合だけです(0.15 / 0.95 から 0.25 / 0.85)。あなたのチームでそれより少なければ、全体の効果は小さくなります。

## 節約が小さくなる場合

- リポジトリが少ない、またはワークフローが 1 つだけ:監視するものが少ない。
- 現在だれも CI を手作業で監視していない、またはすでに原因を示すアラートがある。
- アラートが読まれない。読むのにも時間がかかり、理由なく無視したり消音したりすると節約はなくなる。

## 自分の利用での測り方

1. 導入前:通常の 1 週間、CI を手作業で見るたびにその分数と、仕分けた失敗実行ごとの原因が分かるまでの分数を記録する。
2. 導入後:モニターを開いたまま 1 週間、同じ記録をとる。スコア(回復までの時間)と失敗の記録帳(24 時間と 7 日の傾向)で、失敗がより早く解消されているかが分かる。
3. 各グループの節約率は 1 - 導入後 / 導入前。85〜95 % と比べる。
4. 全体の効果は、節約した時間をその週の総労働時間で割る。15〜25 % と比べる。

### 架空の数値による例

ある人が Actions タブを見るのに 1 日 20 分(5 日間の週で 100 分)、失敗した実行を週 4 件、1 件 30 分で仕分ける(120 分):合計 220 分。85〜95 % を節約すると、187〜209 分が空きます。これらの数値は計算を示すための架空のものです。ご自身の数値を使ってください。


## モニターで測る

このガイドの計算は、あなた自身のメモを使ってページが代わりに行えます。`productivity.enabled`(設定の分析)をオンにして、「導入前」と「導入後」のメモをそこに書いてください。分析セクションに、作業ごとの週あたりの節約分の推定が表示されます。「導入前」を書いていない作業は **データなし** と表示し、あなた自身の「導入後」のメモではなくこのガイドの割合から出た節約は **仮定(未測定)** と表示し、85〜95 % や 15〜25 % を測定値として示すことはありません。[ANALYTICS_jpn.md](ANALYTICS_jpn.md) を参照してください。

# 動作モード: 通常・高速・ターボ

しばらく（たとえば1時間）何かをより近くで見たいときは、API のクォータを早く使ってしまっても、モニターをより速いモードに切り替えられます。ゲージのアイコンの付いた選択ボックスはヘッダーにあり、コンソールでは `--mode fast` または `--mode turbo` に `--mode-minutes 60` を付けます。

| モード | 変わるもの | 既定値 |
|---|---|---|
| **normal** | なし: あなた自身の設定 | あなたの値 |
| **fast**（高速） | 更新間隔、コールド更新、リポジトリごとの run 数、ホット期間 | 30 秒、300 秒、30 run、6 時間 |
| **turbo** | 同じ項目をさらに強化 | 15 秒、90 秒、50 run、12 時間 |

プリセットは `actions_monitor.json` の `modes` ブロック（`modes.fast`、`modes.turbo`、`modes.default_minutes`、`modes.start`）で、自由に編集できます。プリセットがあなた自身の設定より遅く、または小さくすることはなく、GitHub のセカンダリ制限を避けるため 10 秒未満にはなりません（制限に当たると、モニターは最低1分、その後はさらに長く待ちます）。

**開始前に**、ページは最悪の場合の1時間あたりの呼び出し数、キャッシュが通常節約する量（`304` を返す条件付き読み取りはプライマリのクォータを消費しません）、残りのクォータがどのくらいもつかを表示します。時間が来たとき（ヘッダーがカウントダウンします）と、残りのクォータが `min_rate_remaining` を下回ったときに、**自動で通常に戻り**、理由が通知され、コンソールにも表示されます。**ログインなしでは GitHub は1時間に60回しか許可しない**ため、高速とターボは理由付きで無効になります（`gh auth login` を実行してください）。

モードの変更はローカルの設定で、他の変更と同様にページの使い捨てトークンが必要です。メモリ上にのみ存在し（`modes.start` を自分で書かない限り、再起動すると通常に戻ります）、どこにも何も送信しません。両方のエディションで動作し、フル版のセンチネルは独自の間隔と呼び出し予算（`sentinel.budget_per_hour`）を保ちます（[センチネル](SENTINEL_jpn.md)を参照）。コンソールのバナーと状態行には現在のモードが表示されます。

## 節約モード(クォータの極端な節約)

ファストやターボの逆で、多くのツール(エージェント、AI ツール、スクリプト)がアカウントの同じ 1 時間 5000 回の呼び出しを消費する場合のためのモードです。`low` では、モニターはアクティブなリポジトリ(実行中の run や赤いワークフロー)だけを 4 分ごと、その他を 30 分ごとに、短い run 一覧と 2 時間だけの「アクティブ」判定で読み取ります。クォータ(`rate_limit`、無料)は毎サイクル読み取ります。常に許可され(消費が少ないため)、手動で選んだ場合は自動では解除されず、各数値は下部バーに最終取得時刻を保つため、古い数値が新しく見えることはありません。ブリーフと `/api/ai/state` はデータの経過時間とともに `working mode low` と伝えます。

`modes.auto_low`(既定で有効):残り呼び出し数が `modes.auto_low_enter`(1000)を下回ると自動で節約モードに入り、`modes.auto_low_exit`(2500)を超えるかクォータが更新されると通常に戻ります。2 つの値は、行き来を繰り返さないよう意図的に異なります。節約モードの値は設定ファイルの `modes.low`(`refresh_seconds`、`cold_refresh_seconds`、`runs_per_repo`、`hot_hours`)にあり、より遅い自分の設定が速められることはありません。既に読み取った赤いアラートは節約モード中も一覧に残ります。

# リポジトリとチームの健全性

Complete のみ。モニターがすでに保持している情報（実行、赤いワークフローと止まった実行、各センチネルの未解決アラート、リリースの準備状況）から作る、読み取り専用の 2 つのビューです。GitHub は呼び出しません。

## リポジトリの健全性の構成

| 要素 | 内容 |
|---|---|
| CI | 直近 24 時間の成功と失敗、現在赤いワークフロー、止まっている実行 |
| アラート | CI・Collab・セキュリティの各センチネルの未解決アラートすべて（センチネル別・レベル別） |
| リリース | リポジトリにあれば、リリース準備状況の行 |
| アクティビティ | 最後の実行の開始時刻と 7 日間の実行数 |
| 確認したもの | 各センチネルの状態：正常、低下、一時停止、エラー、オフ |

状態は **不良**（赤いワークフロー、またはレベルが重大かエラーのアラート）、**警告**（警告アラートまたは止まった実行）、**OK**、**未確認**（判断材料なし）のいずれかです。どのセンチネルも見ていない、または読み取れなかったリポジトリは OK とは表示されず、「完全には確認できていません」と確認できなかったものを挙げます。リスクはランキングの並べ替えに使う数値で、赤いワークフロー（30）、止まった実行（10）、重大（25）・エラー（10）・警告（3）・情報（1）のアラートごとに加点され、重みはすべてのリポジトリで同じです。 すべてのセンチネルがエラー・一時停止・劣化の状態（またはすべてオフで 1 週間何も実行されていない）のとき、静かなリポジトリは OK ではなく「未確認」と表示され、ランキングの行にはアスタリスクが付き、読み取れなかったセンチネルが並びます（`not_fully_seen`。合計にも数えられます）。

## 見る場所

- **チーム**タブ：ランキング（人の手が必要なリポジトリが先頭）、合計、エコシステム別・センチネル別の数、そして 3 つのフィルター（エコシステム、最低の重大度、名前の一部）。リポジトリをクリックすると詳細が開きます。
- 壁掛け画面用のディープリンク：`?view=team&chrome=0`、`?view=repos&chrome=0`、`?view=repo&repo=owner/name&chrome=0`。
- API：`GET /api/team/health?ecosystem=&severity=&q=&label=` と `GET /api/repos/<owner>/<repo>/health`。どちらもアカウントを見る権限が必要で、応答には `schema: 1` が付きます。不明なリポジトリは 404 と `code: repo_unknown` を返します。
- Lite 版は実行のシンプルな表示を保ち、このタブもルートもありません。

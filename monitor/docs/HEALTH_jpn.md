# リポジトリとチームの健全性

Complete のみ。モニターがすでに保持している情報（実行、赤いワークフローと止まった実行、各センチネルの未解決アラート、リリースの準備状況）から作る、読み取り専用の 2 つのビューです。GitHub は呼び出しません。

## リポジトリの健全性の構成

| 要素 | 内容 |
|---|---|
| CI | 直近 24 時間の成功と失敗、現在赤いワークフロー、止まっている実行 |
| アラート | CI・Collab・セキュリティの各センチネルの未解決アラートすべて（センチネル別・レベル別） |
| リリース | リポジトリにあれば、リリース準備状況の行 |
| アクティビティ | 最後の実行の開始時刻と 7 日間の実行数 |
| 確認したもの | 各センチネルの状態：正常、低下、一時停止、エラー、オフ |

状態は **不良**（赤いワークフロー、またはレベルが重大かエラーのアラート）、**警告**（警告アラートまたは止まった実行）、**OK**、**未確認**（判断材料なし）のいずれかです。どのセンチネルも見ていない、または読み取れなかったリポジトリは OK とは表示されず、「完全には確認できていません」と確認できなかったものを挙げます。リスクはランキングの並べ替えに使う数値で、赤いワークフロー（30）、止まった実行（10）、重大（25）・エラー（10）・警告（3）・情報（1）のアラートごとに加点され、重みはすべてのリポジトリで同じです。 すべてのセンチネルがエラー・一時停止・劣化の状態（またはすべてオフで 1 週間何も実行されていない）のとき、静かなリポジトリは OK ではなく「未確認」と表示され、ランキングの行にはアスタリスクが付き、読み取れなかったセンチネルが並びます（`not_fully_seen`。合計にも数えられます）。

## 見る場所

- **チーム**タブ：ランキング（人の手が必要なリポジトリが先頭）、合計、エコシステム別・センチネル別の数、そして 3 つのフィルター（エコシステム、最低の重大度、名前の一部）。リポジトリをクリックすると詳細が開きます。
- 壁掛け画面用のディープリンク：`?view=team&chrome=0`、`?view=repos&chrome=0`、`?view=repo&repo=owner/name&chrome=0`。
- API：`GET /api/team/health?ecosystem=&severity=&q=&label=` と `GET /api/repos/<owner>/<repo>/health`。どちらもアカウントを見る権限が必要で、応答には `schema: 1` が付きます。不明なリポジトリは 404 と `code: repo_unknown` を返します。
- Lite 版は実行のシンプルな表示を保ち、このタブもルートもありません。

## 数千のリポジトリと戻された時計

チームの健全性は、実行、赤いワークフロー、実行中の実行、アラートをリポジトリごとに一度だけまとめるため、コストはリポジトリ数×実行数ではなくデータ量に比例します。1つのリポジトリだけを求めると、その表示だけを作ります。

未来にある保存済みの時刻(電池式の時計がなく古い日付で起動するコンピューターや、手で修正された時計)は信用されません。スコア、古いデータの削除、定期レポートはすぐに処理されて正しい時刻を書き込み、古い時計が追いつくのを待ちません。

## フリートビュー(数百のリポジトリ)

**チーム**タブには、数百のリポジトリを持つアカウント向けの第2セクション「フリート」があります。リポジトリをグループ化し(`fleet.group_by`:エコシステム、ラベル、状態、なし)、各グループを並べ替え(`fleet.sort`:リスク、名前、最終実行、状態)、一度に `fleet.page_size` 行(既定は50)を「前へ」「次へ」で表示します。ページは `GET /api/team/fleet?ecosystem=&severity=&q=&label=&group=&sort=&saved=`(読み取り専用、最大5,000行、切り詰めは `truncated` で通知)からすべての行を一度だけ受け取り、1ページ分だけ描画するので、アカウントの規模で重くなりません。

*ラベル*はリポジトリ名のパターンです。`fleet.labels` には `team-*=backend` のような行を指定し、最初に一致したパターンがラベルになります。ラベルでグループ化すると、1つのモニターで組織やチームを区別できます。`fleet.saved_filters` には `attention=bad||backend|`(名前、最低重大度、エコシステム、ラベル、テキスト。名前以降は空でも可)のような行を指定し、作成済みフィルターとして表示します。フリートの上にあるランキングは変わりません。

**実行中の run をすべて。** リポジトリの健全性(`ci.active`、リポジトリのダイアログでは「現在実行中」)は、実行中の run をワークフローごとに数えます。同じワークフローの 2 つの run が同時に動いている場合(並行リリース、ブランチごとの run)も両方を数え、実行中と待機中の数、ブランチごとの最新の run を示します。フリートの行には `running` と `queued` が付きます。`fleet.show_all_active` をオフにすると、ワークフローは最新の run だけを表示します。

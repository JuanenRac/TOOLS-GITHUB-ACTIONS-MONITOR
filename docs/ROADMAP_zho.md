# 路线图

当前版本放不下的想法,不承诺顺序。它们是方向而非承诺;推动其中之一的最佳方式是提交 issue 或 pull request。

## 1.6.6 已完成

1.6.5 之后的修复:网络模式现在可在 HTTPS 下从页面使用(来源检查遵循会话的协议),架构中标记为安全的设置只能在本机修改,`act` 在 Stop 后释放运行并关闭管道,网络模式监听所有接口时设置页显示红色横幅,可以用 POST 代替地址打开会话,`--doctor` 和关于面板新增被忽略失败的计数器,`tools/make_screenshots.py` 会说明自己的行为且图片已重新拍摄,更新历史已翻译为八种语言。

## 1.6.5 已完成

一次完整性与安全版本，没有大型新功能：绿色提交需要仓库的必需工作流，fetch 失败会阻止触发，目录不能指定工具文件夹之外的工具或更改 `dry_run`/`ref`，没有记录提交校验的批次不再提供签名；`act` 留在工作区内，停止会结束运行的整个进程树和容器；网络模式可提供 HTTPS，锁定错误令牌，仅接受 IPv4；Webhook 拒绝重放与洪泛；MCP 服务器能承受格式错误的消息；`max_per_hour` 统计消息；设置在锁下保存；保存的令牌只交给 `gh`；`--doctor` 警告危险的组合；干净安装测试成为发布检查的独立阶段。

## 1.6.4 已完成

精简版与演示的隔离测试、更新检查关闭或离线安装时完全不发网络请求、以选择启动器开头的 README、`--doctor --json`、网络模式的常驻提示条、帮助及其文档的八种语言,以及可选功能(网络模式、监视器保存的令牌、对 GitHub 的操作、`act`、构件的本地副本、自托管运行器、OpenTelemetry、按作业标签的 FinOps);见更新日志和 `ADVANCED.md`。

## 下一步

1.6.4 没有做到的,以及原因:

- **已决定,1.6.6 未完成**:对外部 AI 的主动通知(默认关闭,每个提供方首次确认,只发送已过滤的封闭列表字段,每小时调用次数和费用上限,密钥通过环境变量名提供,AI 绝不执行任何操作)及其对外命令变体(封闭列表,不用 shell);以及在一个页面中显示多个所有者的仓库(监视器只用名称识别仓库,因此每个标识符都需要所有者;这是多账号的基础)。每一项都是需要自己的设计和测试的独立功能,所以 1.6.6 先完成了修复。
- **其余七种语言中较旧的更新日志条目**:从 1.6.6 起,帮助以每种语言显示历史,但只有最新条目已翻译;较旧的条目在已翻译的提示下保留英文原文,将按版本从新到旧逐个翻译。
- **默认端口代理之后的 HTTPS**:检查会把 `Host` 和 `Origin` 与监视器的端口比较,因此在 443 端口上转发不带端口 `Host` 的代理暂不支持;页面可通过直接的 TLS 端口或保留端口的代理使用。
- **一个页面里多个所有者**:监视器仅凭名称识别仓库(运行、哨兵、缓存、导出),两个所有者若有同名仓库会混在一起。组织会被列出,每个由各自的监视器监视(`github_owner`)。在一个页面中实现需要在每个标识符中加入所有者。
- **用能读取账单报告的登录验证**:没有 `user` 权限范围的登录得到的真实答复是“未找到”,监视器退回估算(已验证);数字本身尚未与账单账户对照。
- **`quotas.json` 中大型运行器的价格**来自对公开价目表的记忆,标记为未验证;请与 GitHub 账单页面比对并编辑该文件。
- **`gh copilot`**:其参数用 `gh copilot -- --help` 检查,这需要 Copilot 命令行;此处未安装,因此仍未验证。
- **通知、webhook、Enterprise Server 和服务示例**对真实服务的验证:`tools/manual_check_live.py` 可手动检查;它们需要你的渠道和主机,所以没有在此运行。
- **终端应用**可编辑简单设置并显示 AI 状态;单个红色工作流的解释以及列表和映射的编辑仍在页面中。
- **会下载或安装的新版本检查**:永不;监视器只会提示。

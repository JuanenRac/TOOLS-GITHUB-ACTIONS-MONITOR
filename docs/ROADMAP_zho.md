# 路线图

当前版本放不下的想法,不承诺顺序。它们是方向而非承诺;推动其中之一的最佳方式是提交 issue 或 pull request。

## 1.7.6 已完成

监控器与 AI 工具的联动: 信息流始终与页面一致, 每条告警都说明为何变红, 事件流和三个 MCP 工具推送新消息, 一条命令即可安装联动脚本, 底部栏显示是否有 AI 已连接, 所有状态文件仅其所有者可读。

## 1.7.5 已完成

命令行以专用名称读取访问令牌，网络模式默认更安全（对网络隐藏本机地址、可关闭旧的 ?access= 地址、拒绝本地网络上的通知目标、对明文 HTTP 发出警告），面向人的时间使用你自己的时区，警报可以静音到该项目发生变化为止，并修正了给出错误结果的计数和检查。

## 1.7.4 已完成

页面底部的栏，显示最重要的提示（以及显示全部提示的窗口）、连接、配额、最近一次读取、模式、地址和时钟；全屏按钮；可按一列或多列排序并可自选列的“仓库”和“历史”表格；作为运行中监视器客户端的命令行 `monitor_cli.py`（`status`、`health`、`alerts`、`accounts`、`live`、`doctor`，支持 `--json` 和稳定的退出码）及其八种语言的指南；经过顺序检查的更新日志、不再内含历史的软件包 README，以及重新绘制的图片。

## 1.7.3 已完成

第二个哨兵，用于 Issue 和拉取请求（Collab，默认关闭，只读，按自己的周期运行）；一个汇总所有哨兵警报并可按来源和级别筛选的“警报”标签页；会自行结束的本地静音（警报、规则或哨兵；`alerts.mute_hours`）；让某项被忽略的标签；`GET /api/alerts` 与 `GET /api/events`；实时视图检查清单；八种语言的 Collab 哨兵指南；以及重新绘制的图片。

## 1.7.2 已完成

按便于阅读的顺序并使用网格排列的标题栏数字、固定在右上角的快捷控制（仅热点、速度、生态系统健康）、只在侧边栏中的设置、帮助和关于、移出标题栏的新版本通知，以及不再在代码旁留下文件的测试。

## 1.7.1 已完成

带侧边栏的页面（徽标、账户切换器、可折叠分组的栏目、帮助），以及在自动、浅色和深色之外的十六个主题（来自报警系统 Studio）；还有放在契约（`BaseSentinel`、`Alert`、`SentinelRegistry`、`SentinelCI`）之后的 CI 哨兵，这样无需监视器了解每个哨兵的作用，就能加入后续的哨兵。显示和判断的内容不变。

## 1.7.0 已完成

完整版支持多个账户，每个账户都是监督程序下独立的监视器（`accounts/<id>/`、`--accounts`、`--account`、`--migrate-accounts`），并提供账户的 API、供所有账户使用的一个 webhook、带切换器和所有账户卡片的页面、按地址选择的视图（`?view=` 和 `?chrome=0`），以及显示 webhook 接收器状态的实时视图。精简版保持不变。

## 1.6.8 已完成

1.6.7 的 HTTPS 代理已用 443 端口上的真实代理验证(`tools/manual_check_live.py proxy`,以及贯穿 TLS 客户端、反向代理和监视器的测试),图片已重新拍摄并新增两张网络模式的图片,更新历史已将 1.6.8 至 1.6.3 翻译为其他七种语言。

## 1.6.7 已完成

默认 443 端口上的 HTTPS 代理现在可以配合网络模式使用(`listen.proxy_public_host`,默认为空:代理的这一个公开名称可以不带端口被接受,仅限 HTTPS,并且只能在本机上更改),更新历史已将 1.6.7、1.6.6 和 1.6.5 翻译为其他七种语言。

## 1.6.6 已完成

1.6.5 之后的修复:网络模式现在可在 HTTPS 下从页面使用(来源检查遵循会话的协议),架构中标记为安全的设置只能在本机修改,`act` 在 Stop 后释放运行并关闭管道,网络模式监听所有接口时设置页显示红色横幅,可以用 POST 代替地址打开会话,`--doctor` 和关于面板新增被忽略失败的计数器,`tools/make_screenshots.py` 会说明自己的行为且图片已重新拍摄,更新历史已翻译为八种语言。

## 1.6.5 已完成

一次完整性与安全版本，没有大型新功能：绿色提交需要仓库的必需工作流，fetch 失败会阻止触发，目录不能指定工具文件夹之外的工具或更改 `dry_run`/`ref`，没有记录提交校验的批次不再提供签名；`act` 留在工作区内，停止会结束运行的整个进程树和容器；网络模式可提供 HTTPS，锁定错误令牌，仅接受 IPv4；Webhook 拒绝重放与洪泛；MCP 服务器能承受格式错误的消息；`max_per_hour` 统计消息；设置在锁下保存；保存的令牌只交给 `gh`；`--doctor` 警告危险的组合；干净安装测试成为发布检查的独立阶段。

## 1.6.4 已完成

精简版与演示的隔离测试、更新检查关闭或离线安装时完全不发网络请求、以选择启动器开头的 README、`--doctor --json`、网络模式的常驻提示条、帮助及其文档的八种语言,以及可选功能(网络模式、监视器保存的令牌、对 GitHub 的操作、`act`、构件的本地副本、自托管运行器、OpenTelemetry、按作业标签的 FinOps);见更新日志和 `ADVANCED.md`。

## 下一步

1.6.4 没有做到的,以及原因:

- **已决定,1.6.6 未完成**:对外部 AI 的主动通知(默认关闭,每个提供方首次确认,只发送已过滤的封闭列表字段,每小时调用次数和费用上限,密钥通过环境变量名提供,AI 绝不执行任何操作)及其对外命令变体(封闭列表,不用 shell);以及在一个页面中显示多个所有者的仓库(监视器只用名称识别仓库,因此每个标识符都需要所有者;这是多账号的基础)。每一项都是需要自己的设计和测试的独立功能,所以 1.6.6 先完成了修复。
- **其余七种语言中较旧的更新日志条目**:帮助以每种语言显示历史,1.6.8 至 1.6.3 已翻译;1.6.2 及更早的条目在已翻译的提示下保留英文,并将按从新到旧的顺序逐个版本翻译。
- **一个进程、一个页面里的多个所有者**：自 1.7.0 起每个账户都是独立的监视器，页面把它们并排显示，但在一个监视器内部仓库仍只按名称识别，因此同一个监视器里的两个所有者会混在一起。1.7.0 的账户是把它们分开的办法；把它们合并到一个进程、并在每个标识符中带上所有者，是尚待完成的部分。
- **用能读取账单报告的登录验证**:没有 `user` 权限范围的登录得到的真实答复是“未找到”,监视器退回估算(已验证);数字本身尚未与账单账户对照。
- **`quotas.json` 中大型运行器的价格**来自对公开价目表的记忆,标记为未验证;请与 GitHub 账单页面比对并编辑该文件。
- **`gh copilot`**:其参数用 `gh copilot -- --help` 检查,这需要 Copilot 命令行;此处未安装,因此仍未验证。
- **通知、webhook、Enterprise Server 和服务示例**对真实服务的验证:`tools/manual_check_live.py` 可手动检查;它们需要你的渠道和主机,所以没有在此运行。
- **终端应用**可编辑简单设置并显示 AI 状态;单个红色工作流的解释以及列表和映射的编辑仍在页面中。
- **会下载或安装的新版本检查**:永不;监视器只会提示。

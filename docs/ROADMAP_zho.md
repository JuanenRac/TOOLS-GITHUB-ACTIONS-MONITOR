# 路线图

当前版本放不下的想法,不承诺顺序。它们是方向而非承诺;推动其中之一的最佳方式是提交 issue 或 pull request。

## 1.6.4 已完成

精简版与演示的隔离测试、更新检查关闭或离线安装时完全不发网络请求、以选择启动器开头的 README、`--doctor --json`、网络模式的常驻提示条、帮助及其文档的八种语言,以及可选功能(网络模式、监视器保存的令牌、对 GitHub 的操作、`act`、构件的本地副本、自托管运行器、OpenTelemetry、按作业标签的 FinOps);见更新日志和 `ADVANCED.md`。

## 下一步

1.6.4 没有做到的,以及原因:

- **一个页面里多个所有者**:监视器仅凭名称识别仓库(运行、哨兵、缓存、导出),两个所有者若有同名仓库会混在一起。组织会被列出,每个由各自的监视器监视(`github_owner`)。在一个页面中实现需要在每个标识符中加入所有者。
- **用能读取账单报告的登录验证**:没有 `user` 权限范围的登录得到的真实答复是“未找到”,监视器退回估算(已验证);数字本身尚未与账单账户对照。
- **`quotas.json` 中大型运行器的价格**来自对公开价目表的记忆,标记为未验证;请与 GitHub 账单页面比对并编辑该文件。
- **`gh copilot`**:其参数用 `gh copilot -- --help` 检查,这需要 Copilot 命令行;此处未安装,因此仍未验证。
- **通知、webhook、Enterprise Server 和服务示例**对真实服务的验证:`tools/manual_check_live.py` 可手动检查;它们需要你的渠道和主机,所以没有在此运行。
- **终端应用**可编辑简单设置并显示 AI 状态;单个红色工作流的解释以及列表和映射的编辑仍在页面中。
- **会下载或安装的新版本检查**:永不;监视器只会提示。

## 以后

- **更多通知适配器**:ntfy、Microsoft Teams,以及经本地中继的电子邮件。
- **一个页面里多个账户**:目前每个账户由各自的监视器运行。
- **通过代理获取运行器的硬件遥测**:目前只读取可选的 node exporter 端点。

# 路线图

已发布的、接下来的和仍只是想法的内容,按确定程度排列。它们是方向而非承诺;推动其中一项最好的办法是提交 issue 或拉取请求。

## 监视器现在的位置

版本 2.2.0。lite 版显示正在运行的和失败的内容。完整版增加三个哨兵(CI、Collab 和 Security)、一份警报列表、多个账户和带角色的团队、每个账户的评分、每个仓库和团队的健康状况、定时报告、操作日志、通知(ntfy、Teams、电子邮件和 Apprise)、带兼容服务预设的可选 AI 助手、Docker 服务模式,以及适配从手机到 4K 各种屏幕尺寸的页面。从本版本起发布文件带签名; 插件、外部 CI 源、安全态势检查、协作与舰队视图、严格只读模式和合规报告均已提供, 开启前全部关闭。

## 计划,按此顺序

每个版本只包含真实内容:没有真实内容可加的版本会被跳过,绝不会空着发布。除非指南另有说明,这里的内容均不视为已在真实服务上得到验证。

### 2.2.1 - 仅修正

对 2.2.0 复查后的修正版本, 不含新功能。新的可选部分尚未对照试过的内容 (真实的外部 CI 服务器、真实的组织、真实的 AI 服务商、跨多个版本的签名与证明) 在此版本及之后的版本中验证或修正。

监视器自身的工作流遵守卫生哨兵将向他人提出的要求:固定到提交的 action、最小权限,以及每个作业的时间限制。

## 1.8.2 至 2.2.0 已完成

### 2.2.0 - 签名发布、面向较大部署的可选部分, 以及更适合手机的页面

2.2.0 汇集了原计划用于 2.1.9 和 2.2.0 的全部内容。发布文件带签名, 更新程序会校验; 有新版本时弹窗提示; 每个版本附带两份物料清单和证明。以下功能开启前均关闭: 签名插件与密钥库、由人决定的 AI 提议、只读的外部 CI 源、安全态势检查、需确认操作的协作视图、舰队视图与 API、严格只读模式与网络策略、合规报告、带法律保留的数据保留, 以及签名的操作日志。仓库按来源、所有者和名称区分, 设置分组改为左侧列表, 横持手机时页面可以正常使用。

### 2.1.8 - 2.1.7 的复查：诚实的哨兵、可用的 AI 建议审批、更严格的网络访问、代理隧道和更安全的发布镜像

2.1.8 版本不增加新功能：它修正了对 2.1.7 复查中发现的问题。当运行列表可能隐藏某个工作流时，CI 哨兵不再显示绿色；批准或拒绝 AI 建议可以正常工作；被撤销的设备会失去其已打开的数据流；连接有时间和数量上限；代理隧道可用；回退不再覆盖正在进行的更新；容器镜像仅从标签发布；屏幕、展示模式、命令行和文档与程序的实际行为一致。

### 2.1.7 - 始终保持最新的屏幕与展示屏、手机视图、实时投递与恢复、规模与可观测性、诚实的哨兵以及带不可变发布的发布链

2.1.7 版汇集了 2.1.6 与 2.1.7 计划的全部内容。按主题: 屏幕与展示屏(新版本时自动重新加载、车队屏幕、密度、调色板、对比度、过扫描、打印与保存报告); 手机与 PWA(作为应用安装、紧凑视图、二维码配对、命令面板与快捷键); 实时与恢复(Webhook 队列、无需公网地址的 WebSocket、GitHub 状态、心跳); 规模与可观测性(直方图、按桶配额、OpenTelemetry、多工作区、成本与碳排放); 命令行与 AI(输出格式、watch、doctor、需批准的提议、告警历史); 读取诚实、没有误报的哨兵; 以及发布链(不可变发布、zizmor 任务、保留副本与日志的更新器)。

### 2.1.5 - 完整的配置、骗不了的记录与缓存、固定问题的助手、带契约的读取 API 和更丰富的每日趋势

示例文件包含每一项设置，设置页为所有设置显示默认值；配置文件在监视器启动时检查。监视器保存的每条记录都带有其结构的版本，重启后页面立即显示最后一幅画面。哨兵有时间上限，访问审计在操作系统的锁下写入，条件读取的缓存属于读取它的凭据，返回为空的列表绝不轻信。可选开关会查看仍在运行的运行、逐个仓库地判断 Webhook 仓库，并允许从页面更新运行在 systemd 用户服务下的监视器。更新以事件形式显示进度，并经过端到端测试。助手有了专属指南、只读的固定问题、可证明的离网模式以及模型数字的来源；读取 API 有完整的 OpenAPI 文档、契约测试套件和版本头。每日趋势有更多数字、发布标记、阈值和图片副本，哨兵面板中的每个信号都有自己的卡片。

### 2.1.3 - 每个设置都有帮助、“昨天与今天”标签页、更难被滥用的更新菜单以及不再重叠的面板

设置标签页为每个设置显示提示框，说明它的作用、范围或取值、默认值以及开关打开和关闭时的行为。“昨天与今天”有了自己的菜单项。更新菜单在连续失败后会暂停，说明更新被阻止的原因，并且只在进度文件是小的普通文件时才读取它；工作流检查器会截断恶意文件，指南会检查八种语言的结构是否一致，哨兵标签页的折叠面板不再相互覆盖。

### 2.1.2 - 监视器通过菜单自行更新、将一个周期与前一个周期比较，展开的面板延伸到底部

更新菜单（完整版）显示已安装的版本和已发布的版本及其说明，先做副本、将 zip 与 SHA256SUMS 对照、迁移配置并重启后应用更新，新版本无法启动时一键回退；独立的更新工具仍作为回退途径。比较把一个周期与前一个周期并排放置，在无法给出数字时给出诚实的状态，并提供变化报告、一个路由、一个命令、图表标签页的一个部分以及定期报告的一个可选部分。多个进程写入的文件使用操作系统的锁，哨兵标签页中展开的面板延伸到其框的底部，从更新工具启动监视器不再为每次 git 和 gh 调用打开一个控制台窗口，架构图展示了监视器如今的样子。

### 2.1.1 - 供应链与交付两个新哨兵,以及更严格的发布关卡

两个新哨兵默认关闭,仅在 Complete 版中提供,在不向 GitHub 写入任何内容的情况下读取仓库构建了什么、交付了什么:供应链哨兵检查工作流文件中未固定的 action、会移动的分支以及过宽或缺失的权限,交付哨兵则比较发布、标签、变更日志、版本文件和固定的版本。doctor 现在会以红色提示没有密钥的传入 webhook,时钟被调回时 webhook 覆盖状态不再一直在线,发布关卡会把 zip 中每个文件的内容与提交比较,按 unittest 给出的数量接受完整的绿色运行,并能显示套件的进度。

### 2.1.0 - 带主题、徽标和轮播模式的墙面屏幕、可恢复的备份与更新器

墙面屏幕采用产品的主题,并可显示组织的徽标;一个窗口可以在三个屏幕之间轮播,并在出现新的红色时跳转;总览按分组显示整个仓库群的地图;失败的 Dependabot 更新成为独立的警报;每种事件在本机上也有各自的声音。整个安装可以完整复制、校验和恢复,也可按计划执行;doctor 以不变的退出码检查运行状况,并可按需执行清理。更新器可把安装迁移到任何已发布的版本,先复制,出错时回退。发布闸门会指出失败的测试,并接受已经见过的绿色运行;详情面板的状态标签保持在一行,页面的链接通过解析地址来检查,容器指南说明了如何打开第一次会话。

### 2.0.9 - 更安全的独立审计、带分组的菜单、按事件类型区分的声音和只读聊天命令

独立审计加固了监视器:访问令牌默认不再出现在地址中,按模式的静音不再静音非工作流的内容,文本清理器能捕获更多形式的真实日志,带密钥的请求头从不跟随重定向,Webhook 投递会被校验且无法重放,互联网上或私有地址上的提供商需要单独的开关。左侧菜单有带标题的分组,每种事件类型有自己的声音,只读命令可在 Slack 和 Discord 中应答(默认关闭),墙面屏幕跟随主页面的语言,集成 AI 只有一个同时计入主动通知的预算。操作日志可以成为操作的前提条件,并保留你选择数量的轮转文件,一个周期对哨兵的所有阶段只计一次,容器镜像审计的工作流以及它在容器中发现的故障修复也包含在此版本中。

### 2.0.8 - 更安全的 Webhook 密钥、check run 和 Webhook 设置指南(收尾第四阶段的版本)

传入 Webhook 的共享密钥只通过环境变量(或设置所指定的文件)传递,Webhook 也接收 check run 事件,实时视图会说明事件覆盖了多少时间,八种语言的指南(`docs/WEBHOOK.md`)逐步说明如何在 GitHub 中设置 Webhook。对真实账户的研究新增三项:文件已删除的工作流不是可启用的工作流,从未推送过的复刻不算最近推送过,运行器 `codspeed` 被识别为付费的第三方运行器。文档不再声称 macOS 在 CI 中运行。这是收尾第四阶段的版本:审计之前的稳定化版本。

### 2.0.7 - 面向客户端的读取 API、每个复刻的原始仓库以及手动停用的工作流

面向客户端的 `/api/v1/` 读取 API(`me`、`repos` 和 `openapi`,默认关闭,契约已冻结);可选地跟踪每个复刻的原始仓库(`upstream.enabled`,默认关闭,每小时请求数有上限);所有者手动停用的工作流不再算红色,而是单独显示(`ci.disabled_apart`)。

### 2.0.6 - 三个已绘制的墙屏,默认关闭

三个墙屏已绘制完成:概览(评分、车队指示灯、图表、热力图、运行器和配额)、此刻(进行中的运行、队列、待批准、近期失败和实时线)以及哨兵(每个哨兵一张带动画雷达的卡片)。页面自行绘制所有图表,新的失败只闪烁一次然后平静,要求减少动态的用户看不到任何运动,为防烧屏每分钟略微移动,夜间可调暗,一个窗口可在三个页面间轮换,浏览器测试会在 1080p、4K 和竖屏下以八种语言检查它们。墙屏默认关闭(`screens.enabled`),README 和墙屏指南现已展示它们。

### 2.0.5 - 更少的误报红色、休眠仓库和全屏下可见的确认提问

红色现在按事件来源计数:GitHub 为自己创建的工作流(`dynamic/`)既不是红色 CI 也不是文件,隐藏工作流的查询遵循同一来源规则,排队数天的运行被识别为幽灵队列(默认 7 天),无人处理的红色在 30 天后老化并变为不活跃;休眠和不活跃的仓库是独立状态,既非绿色也非红色;复刻仓库只有在最近 90 天内有自己的 CI 时才进入卫生检查、工作流检查和评分;默认分支的保护默认按所有公开来源中实际生效的内容判断;页面的五个确认操作改用页面内的对话框,全屏下也可见。

### 2.0.4 - 按任务选择的模型、独立的菜单和打开正确主题的帮助

监控器的 AI 可以为每类任务使用一个模型、在主模型失败时使用后备链,并为每个模型设置预算,在设置中写明之前全部关闭;警报、报告和经验教训成为三个独立的菜单条目,各有自己的面板、徽标、帮助主题和地址;历史标签页只保留一个计数,而不是每次刷新都累积副本;“本标签页帮助”按钮在每个标签页都会打开当前标签页的主题;工具文件夹不存在时,浏览器测试会干净地跳过。

### 2.0.3 - 大型账户、更少的误报红色、无需克隆的检查和更安全的存储

面向拥有数百个仓库的账户的车队视图、分页列表、请求预算和对运行列表的诚实覆盖;红色只有在仓库自身造成时才计入,等待批准的运行、被弃用的工作流、只响应 issue 的工作流、合并队列和维护分支各得其所;工作流检查器和表面检查通过 API 或稀疏克隆工作,无需克隆;AI 提供商的模型会被读取和核对,页面的每个链接都经过地址过滤器;锁和操作日志在 Windows 上更安全,评分账本不会被覆盖;用于显示器或电视的墙屏(默认关闭);仓库的测试暂时不再在 macOS 上运行。

### 2.0.2 - 更安全的日志、更干净的 AI 文本和更公平的评分

AI 可读取的一切都经过一个认识更多形式机密的清理器,内置助手保留其密钥且不再跟随重定向和代理,操作日志是每个账户一个文件中的一条链且查看者无法读取,镜像和账户的进程不再带有机密,评分会惩罚从未修复的故障且不再把不可读的来源算作干净,另有关于存储、备份、迁移、终端视图和启动器的一长串修复。

### 2.0.1 - 打包与缺失的键

发布的 zip 现在包含 AI 预设文件和软件包的所有其他数据文件,如果 zip 中缺少其中任何一个,发布关卡就会失败;所有账户页面不再显示未翻译的状态键,并且有一项测试检查页面使用的每个键都存在于八个语言目录中。

### 2.0.0 - 成熟

读取 API 与公共接口已冻结：一份记录每个读取端点的键、类型和错误码的契约文件，一个可对任何正在运行的监视器检查它的测试套件和工具，一个固定警报字段以及哨兵和存储方法的测试，以及针对每种用法（简易版、个人、服务、团队）和 API 客户端的八种语言指南。1.9.6 至 1.9.9 在收尾审查之后没有真实内容可加，已被跳过。

### 1.9.5 - 实时事件流

为无法轮询的客户端和墙面屏幕提供入站 Webhook 的实时事件流，默认关闭，只读，并限制监听者数量和每个监听者的时长。

### 1.9.4 - AI 预设

一张包含十二个托管服务和六个本地服务器的表,它们使用监视器已支持的协议;AI 设置中的选择器会填入地址、密钥变量的名称和一个示例模型;本地服务器无需密钥即可工作;主要服务的地址已在其公开文档中核对。

### 1.9.3 - 定期报告与审计日志

包含评分、主要警报和变更的 HTML 与 Markdown 报告模板(PDF 可选),调度器,以及只追加的审计日志,记录谁在何时做了什么,其中不含任何机密。可选,同一版本:带有每个仓库最近一次绿色提交的"发布就绪 / 受阻"视图。

### 1.9.2 - 仓库与团队健康

每个仓库的健康视图(CI、议题和拉取请求、安全、发布就绪度、活跃度)以及带排名、合计和过滤器的团队视图;两者都有页面,并提供适合墙面屏幕的深层链接。可选,同一版本:对照预算的夜间基准面板(相对于每类机器基线的中位数),以及每个发布的软件物料清单和证明面板。

### 1.9.1 - 安全哨兵

第三个哨兵:Dependabot、代码扫描、密钥扫描、分支保护、工作流权限和代码所有者,按信号类型设置规则,在警报标签页中使用同样的过滤器,并对未解决的严重警报在评分中扣分。可选,同一版本:工作流卫生(未固定到提交的 action、没有时间限制的作业、没有权限或并发设置的工作流、对 pull_request_target 的危险用法),基于项目已有的工作流检查器。

### 1.9.0 - 统一评分

按账户和哨兵的指标采集器(成功率、时长、恢复时间、吞吐量),阈值可调的评分引擎,与上一周期相比的趋势,保存在存储中的快照,带迷你折线图的评分组件,评分下降时的警报,以及打印评分的命令行动词。

### 1.8.4 - 稳定化

没有大的新功能。账户之间的隔离、页面、存储、登录与角色、通知、时好时坏的 GitHub、迁移中断后的启动、被强制终止后的恢复、更全面的 doctor、写入 GitHub 的位置、不含令牌的日志、团队模式的安全清单,以及与行为一致的文档。该系列仅在需要时延续到 1.8.9。

### 1.8.3 - 按用户的通知

按用户的偏好(渠道、哨兵、最低级别),根据偏好和角色决定通知谁的分发器,作为简单插件的渠道,以及未读警报的摘要。另外:按运行器统计作业在队列中的等待时间报告,以及因监视路径而被跳过的作业与红色作业分开显示。

### 1.8.2 - 官方 Docker 镜像与服务模式

多阶段镜像、非特权用户、数据与配置卷、有文档的环境变量、带可选反向代理和 TLS 的 compose 示例、供偏好传统安装的人使用的 systemd 单元,以及当监督进程或某账户的周期卡住时会失败的深度健康检查。GitHub 撤销或过期的凭据只会把该账户标记为"失明",触发严重的系统警报,并可在不重启监督进程的情况下替换。备份、升级和作为服务的首次启动都有文档;页面会说明它是在本机、网络上还是在代理之后监听;命令行可针对远程监视器工作。lite 版仍为本地。

## 1.8.0 已完成

## 下一步

1.6.4 没有做到的,以及原因:

- **一个进程、一个页面中的多个所有者**: 从 2.2.0 起仓库按来源、所有者和名称识别, `sources.multi_owner` (默认关闭) 可让一个监视器监视多个所有者; 尚未在两个真实所有者的仓库上验证, 因此 1.7.0 的独立账户仍是稳妥的方式。
- **用能读取账单报告的登录验证**:没有 `user` 权限范围的登录得到的真实答复是“未找到”,监视器退回估算(已验证);数字本身尚未与账单账户对照。
- **`quotas.json` 中大型运行器的价格**来自对公开价目表的记忆,标记为未验证;请与 GitHub 账单页面比对并编辑该文件。
- **`gh copilot`**:其参数用 `gh copilot -- --help` 检查,这需要 Copilot 命令行;此处未安装,因此仍未验证。
- **通知、webhook、Enterprise Server 和服务示例**对真实服务的验证:`tools/manual_check_live.py` 可手动检查;它们需要你的渠道和主机,所以没有在此运行。
- **终端应用**可以编辑简单设置、列表和数字映射,并显示 AI 状态;对单个红色工作流的解释仍留在页面中。
- **只有所有者能在真实安装上证明它们**:在真实仓库上用 Collab 哨兵的多个账户、使用真实密钥的 GitHub App 和只读的第二个账户,以及使用真实证书的 HTTPS 代理。它们靠手动运行(`tools/manual_check_live.py`),不当作已完成。
- **自行安装的新版本**: 永不; 监视器只提示, 由人决定是否更新。
